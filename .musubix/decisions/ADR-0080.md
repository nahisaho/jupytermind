# ADR-0080: Route peer review from persisted manuscript language metadata with explicit blocking on gaps

## Context / 背景
`DES-AISCI-008` (`REQ-AISCI-011`, `REQ-AISCI-012`, `REQ-AISCI-013`,
`CHANGE-001`) controls which sibling skill reviews a manuscript. The
trade-off is whether peer review should be a deterministic branch from
previously recorded metadata or a best-effort heuristic that tries to guess
a usable reviewer even when manuscript provenance is incomplete.

## Decision / 決定
`review_manuscript(handle, invoker)` reads the latest
`manuscript-writing` evidence via `latest_evidence(...)`, extracts the
persisted `language` metadata, and looks it up in the fixed
`PEER_REVIEW_DEPENDENCIES` mapping: `ja` routes to
`japanese-prose@0.3.0` in `review` mode, and `en` routes to
`tech-writer@0.3.0` in `review` mode. The selected skill receives the
manuscript artifact path, and ai-scientist records its findings as a new
`peer-review` evidence artifact in `review_dir`, separate from the original
manuscript evidence.

If the manuscript evidence is missing, lacks `language`, or carries any
unsupported value, ai-scientist raises `PeerReviewBlockedError` instead of
guessing. That makes peer-review routing deterministic, auditable, and
faithfully tied to the manuscript-writing record created earlier.

## Rejected alternatives / 却下した代替案
- **Re-detecting language from the manuscript file contents before each review**: rejected — it would ignore the persisted workflow metadata and make routing depend on heuristic text inspection that can drift after edits or mixed-language sections.
- **Falling back to one reviewer (for example `tech-writer`) when metadata is missing or unsupported**: rejected — a silent fallback would hide missing provenance and could send Japanese content to the wrong reviewer, violating the explicit block-on-missing-metadata requirement.
- **Storing review findings by mutating the manuscript evidence record instead of recording separate `peer-review` evidence**: rejected — manuscript-writing and peer-review are separate phases with separate evidence obligations, so collapsing them would blur phase attribution and weaken completion checks.

## Consequences / 結果
Future reviewer additions must extend the persisted metadata contract and
explicit routing table rather than adding heuristic fallback behavior.
Covered by the acceptance tests in `tests/test_ai_scientist_delegation.py`.
