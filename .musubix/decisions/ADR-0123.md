# ADR-0123: Accept REQ-AIDS-111 (t-SNE) and REQ-AIDS-112 (IsolationForest/LOF) results by version-robust structural/topological invariants, not by literal float/array equality

## Context / 背景
REQ-AIDS-111 adds `clustering.fit_unsupervised_model(method="tsne", ...)`
wrapping `sklearn.manifold.TSNE`, and REQ-AIDS-112 adds
`anomaly_detection.detect_multivariate_anomalies(method=
"isolation_forest"|"lof", ...)` wrapping `sklearn.ensemble.IsolationForest`
and `sklearn.neighbors.LocalOutlierFactor`. `pyproject.toml` pins
`scikit-learn>=1.5` (a floor, not an exact pin). `TSNE`'s internal
gradient-descent optimizer and `IsolationForest`'s internal random
sampling are stochastic algorithms whose exact numeric output is not
guaranteed bit-identical across `scikit-learn` minor/major releases
even with a fixed `random_state`, because internal implementation
details (e.g. solver defaults, parallelization order, floating-point
accumulation order) can change between releases without changing the
public API contract. Asserting literal embedding coordinates or literal
`IsolationForest` labels for every non-outlier index would therefore
make the acceptance tests version-fragile: a routine `scikit-learn`
upgrade could flip unrelated borderline labels or shift embedding
coordinates without the module's own logic having changed at all,
producing false test failures unrelated to any real regression.
`LocalOutlierFactor`, by contrast, is deterministic given fixed data and
`n_neighbors` (no internal randomness), so this concern applies to
`TSNE` and `IsolationForest` specifically, with `LOF`'s shape/
value-domain invariant serving the same version-robustness goal for
API-contract consistency across all 3 methods.

## Decision / 決定
Both requirements' Acceptance criteria are written as version-robust
structural/topological invariants over the stochastic methods' output,
not literal coordinate/label equality:
- REQ-AIDS-111 (t-SNE): the required pass/fail criterion is
  `mean(pairwise Euclidean distance within a cluster) < mean(pairwise
  Euclidean distance between clusters)` on a fixed two-Gaussian-cluster
  fixture — a property that holds for any correct `t-SNE` embedding of
  well-separated clusters regardless of the exact coordinate values a
  particular `scikit-learn` version's optimizer converges to. The
  specific observed values (`mean_within≈6.889`, `mean_between≈63.770`)
  are documented as empirically-verified evidence for the currently
  installed version, not as the pass/fail threshold itself.
- REQ-AIDS-112 (IsolationForest/LOF): the required pass/fail criterion
  is the shape/value-domain/boolean-equivalence invariant (`labels` is a
  length-N list of only `1`/`-1`, `is_outlier[i] == (labels[i] == -1)`
  for every `i`) plus the specific known-outlier-index invariant (the 2
  deliberately injected far-outlier points, at indices 18/19 of the
  fixture, must be flagged `-1`/`True` by both methods). The exact
  labels reported for the fixture's currently-installed
  `scikit-learn>=1.5` version are documented as empirically-verified,
  version-specific evidence, explicitly marked informative-only (not a
  required pass/fail criterion) for arbitrary future `scikit-learn`
  versions.
This design decision is shared by both requirements because they are
the same underlying acceptance-testing concern (stochastic
scikit-learn algorithm, fixed `random_state`, no cross-version
bit-identical guarantee) applied to 2 different new methods added in
the same change.

## Rejected alternatives / 却下した代替案
**Assert literal embedding coordinates / literal per-index labels for
every sample, pinned to the exact values observed with the
currently-installed `scikit-learn` version**: rejected — this is
exactly the version-fragility this ADR exists to avoid; it would force
every future `scikit-learn` upgrade (even floor-compatible ones under
the existing `>=1.5` pin) to be treated as a design/requirements change
merely to re-record new literal values, with no corresponding change in
the module's own logic.
**Pin `scikit-learn` to an exact version (e.g. `scikit-learn==1.5.0`)
instead of relaxing the acceptance criterion**: rejected — an exact pin
would make literal-value acceptance tests stable, but it reverses this
project's existing floor-only dependency convention
(`scikit-learn>=1.5`, matching `scipy`/`statsmodels`'s own floor-only
pins elsewhere in `pyproject.toml`) for the sake of 2 new methods only,
and would block routine security/bugfix upgrades of a shared dependency
used by many other already-shipped modules.
**Use a fixed random seed and assume that alone guarantees
cross-version determinism**: rejected — empirically false for `TSNE`'s
optimizer and `IsolationForest`'s sampling; a fixed `random_state`
guarantees reproducibility only within a single library version/build,
not across versions, so this alone cannot be the acceptance mechanism.

## Consequences / 結果
Future `scikit-learn` upgrades that satisfy the documented structural
invariants (within/between-cluster separation for `t-SNE`; shape,
value-domain, boolean-equivalence, and the 2 known-outlier flags for
`IsolationForest`/`LOF`) pass acceptance without any requirements.md or
design.md edit. A `scikit-learn` upgrade that breaks one of these
invariants is a genuine, actionable signal (either a real regression in
how this module calls the library, or a sufficiently disruptive library
behavior change worth a fresh design review) rather than acceptance-test
noise from unrelated numeric drift.
