# ADR-0068: Detect `RenderedChart` via `isinstance` inside `record_chart`, not via a parallel parameter

## Context / 背景
`DES-AIDS-049` (REQ-AIDS-061, GitHub #35) addresses the second half of the
chart-metadata loss: once `render_chart` can produce a `RenderedChart`
(ADR-0067), `record_chart` must persist that metadata into the newly
created notebook cell's `cell["metadata"]["chart"]` so `notebook_audit`
can surface it, while never regressing the existing "unaudited" finding
for plain-`bytes` callers.

## Decision / 決定
`record_chart` performs an `isinstance(png_bytes, RenderedChart)` check.
When true, it serializes `.chart_metadata` (title, xlabel, ylabel,
legend, missing_glyphs as a list) into `cell["metadata"]["chart"]` before
appending the cell. When `png_bytes` is plain `bytes`,
`cell["metadata"]["chart"]` is left unset exactly as today, preserving
`notebook_audit.audit_visual_outputs`'s "unaudited"/missing-glyph
detection path for non-conforming callers. The public
`record_chart(handle, code, png_bytes: bytes) -> int` signature is left
unchanged, since `RenderedChart` is itself a `bytes` subtype. (A later,
separate design extension additively adds a `legend_title` field to the
same serialized metadata mapping; this ADR documents the original
five-field decision scoped to REQ-AIDS-061.)

## Rejected alternatives / 却下した代替案
- **Adding a separate, explicit `chart_metadata: ChartMetadata | None =
  None` parameter to `record_chart`**: rejected — although such a
  parameter could be optional (not forcing every unrelated call site to
  change), it would still require every metadata-producing caller to
  extract and pass `chart_metadata` explicitly, duplicating information
  already carried on the `RenderedChart` instance itself, and would
  allow a caller to pass mismatched bytes/metadata pairs that
  `isinstance`-based detection cannot produce.
- **Always requiring `png_bytes` to be a `RenderedChart` (rejecting plain
  `bytes` with a `TypeError`)**: rejected — this is a breaking signature
  change for any caller, present or future, that legitimately has only
  raw `bytes` (e.g. a pre-rendered image loaded from disk), and conflicts
  with `notebook_audit`'s established "unaudited" finding for exactly
  that case, which this design explicitly preserves.
- **Detecting "is this a chart with metadata" via `hasattr(png_bytes,
  "chart_metadata")` instead of `isinstance`**: rejected — a narrower,
  explicit `isinstance(png_bytes, RenderedChart)` check is unambiguous
  and cannot be accidentally satisfied by an unrelated object that
  happens to define a same-named attribute.

## Consequences / 結果
This is an intentional, documented semantic extension of `record_chart`'s
contract (a caller passing a `RenderedChart` now observes
`cell["metadata"]["chart"]` populated, where it previously never was) —
not a value-preserving change for every conceivable consumer. Any future
`record_chart` caller relying on the prior always-absent-metadata
behavior must be updated to expect this. Covered by the REQ-AIDS-061
acceptance tests in `tests/test_visualization.py`.
