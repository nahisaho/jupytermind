# ADR-0056: Three-way holdout selection-bias evaluator design

## Context / 背景
`DES-AIDS-092` (REQ-AIDS-092) must measure "selection optimism" — how much
of an apparent improvement from picking the best of several candidate
configurations is an artifact of using the same data both to pick the
winner and to measure its improvement. This requires three genuinely
disjoint row subsets (train/selection/evaluation) and a defensible rule for
who picks the winning candidate and how non-empty partitions are
guaranteed. A rubber-duck review during implementation found that a first
draft let the caller-supplied `evaluate_candidate_fn` return an arbitrary
`selected_candidate` (trusting it even if it had been chosen using
evaluation-partition metrics instead of selection-partition metrics) and
let skewed fractions on small `len(df)` silently produce empty partitions
(e.g., 3 rows at 0.8/0.1/0.1 fractions yielding `[3, 0, 0]`), both of which
would defeat the measurement's entire purpose while still returning an
apparently valid result.

## Decision / 決定
1. **Winner selection is computed by the evaluator itself, from
   selection-partition metrics only.** `evaluate_selection_bias_holdout`
   requires `evaluate_candidate_fn` to return `selection_metrics` and
   `evaluation_metrics` dicts (not a `selected_candidate` string), and
   `_choose_selection_winner` derives the winner via
   `max(candidates, key=lambda c: (selection_metrics[c], -candidates.index(c)))` —
   i.e. highest selection-partition score wins, with ties broken
   deterministically by original candidate order. This makes it structurally
   impossible for evaluation-partition data to influence which candidate is
   declared the winner.
2. **Partition sizing is guaranteed non-empty for every supported input.**
   `_split_holdout_partitions` computes initial counts by flooring
   `fraction * total_rows`, distributes the rounding remainder to the
   partitions with the largest fractional remainder, and then — if any
   partition is still empty — repeatedly donates one row from the
   currently-largest partition to the first empty one until all three are
   non-empty, raising `ValueError` only if `total_rows < 3` (the minimum for
   three non-empty partitions) or fewer than 3 distinct non-empty partitions
   can ever be formed.

## Rejected alternatives / 却下した代替案
- Trusting a caller-returned `selected_candidate` (the original draft):
   rejected because it is the exact defect the rubber-duck review
   reproduced — a callback whose selection metrics preferred candidate "a"
   but whose evaluation metrics preferred "b" was still accepted returning
   "b", silently defeating REQ-AIDS-092's "choose using only the selection
   partition" requirement.
- Raising `ValueError` on any fraction/row-count combination that would
  naively produce an empty partition (reject-only strategy), instead of the
  donor-redistribution strategy: rejected as unnecessarily strict for the
  common, intended use case of small illustrative/notebook datasets (for
  example exactly 3-10 rows with default 0.6/0.2/0.2 fractions) where a
  minimally-adjusted non-empty split is more useful to the caller than an
  outright failure; `ValueError` is still raised for the genuinely
  unsatisfiable case of fewer than 3 rows.
- Stratified or class-balanced partitioning: rejected as out of scope for
  this change — REQ-AIDS-092's acceptance criteria only require disjoint
  random partitions of the specified fractions, and stratification would
  introduce a target-column-type dependency (classification vs regression)
  not present elsewhere in this module.

## Consequences / 結果
Any future change to `evaluate_candidate_fn`'s expected payload shape or to
the partition-sizing rounding/donation rule must preserve both guarantees
above (selection-only winner derivation; guaranteed non-empty partitions),
since both are now load-bearing for REQ-AIDS-092's "measurable optimism"
acceptance criteria and are covered by regression tests
(`TEST-AIDS-224`-`TEST-AIDS-228`).
