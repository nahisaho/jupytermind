# ADR-0055: Three-category adoption classification rule for seed-variability judgment

## Context / 背景
`DES-AIDS-091` (REQ-AIDS-091) must turn a candidate improvement value and the
`DES-AIDS-090` seed-variability summary into an actionable classification a
notebook user can read directly: should this candidate configuration be
adopted, is it indistinguishable from seed noise, or is it actually a
regression?

## Decision / 決定
Classify using three mutually exclusive, exhaustive categories driven by
simple threshold comparison against `summary.seed_variability` (unless the
caller explicitly overrides `threshold`): `"regression"` when
`candidate_improvement < 0`, `"within_seed_variability"` when
`0 <= candidate_improvement <= threshold`, and `"adopt"` only when
`candidate_improvement > threshold`. The decision object always echoes back
both the measured improvement and the threshold used, so downstream
commentary can explain the "why", not just the "what".

## Rejected alternatives / 却下した代替案
- A binary adopt/reject decision without the "within seed variability"
  middle category: rejected because collapsing "no measurable improvement"
  and "worse than baseline" into the same rejection bucket would hide the
  genuinely useful information that a candidate is statistically
  indistinguishable from the baseline, which is actionable differently (keep
  baseline, maybe retry with different seeds) than an outright regression
  (investigate what made it worse).
- A statistical-significance test (e.g., paired t-test p-value threshold)
  instead of a direct variability-range comparison: rejected as
  disproportionate for this requirement's scope, which is explicitly about
  comparing against *observed* repeated-seed noise from `DES-AIDS-090`
  rather than inferring population-level significance; CHANGE-010's existing
  `evaluate_experiment` already offers paired statistical tests for callers
  who need that instead.
- Treating `candidate_improvement == threshold` as `"adopt"` (strict `>=`
  boundary) rather than `"within_seed_variability"`: rejected because an
  improvement exactly equal to the worst-observed seed-to-seed swing is, by
  definition, not distinguishable from noise; a strict `>` boundary is the
  conservative, defensible choice and keeps the three categories' boundary
  conditions unambiguous.

## Consequences / 結果
Because the default threshold is sourced directly from `DES-AIDS-090`'s
range statistic, any future change to that statistic (see ADR-0054) changes
this classifier's default behavior; callers needing a different sensitivity
can always pass an explicit `threshold` override.
