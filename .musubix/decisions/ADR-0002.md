# ADR-0002: Datalayer jupyter-mcp-server as the Jupyter MCP execution backend

## Context / 背景
REQ-AIDS-003 requires all analysis code to execute through a Jupyter MCP
server against the project notebook kernel. The user chose between adopting
an existing MCP server or building one from scratch.

## Decision / 決定
Use the Datalayer `jupyter-mcp-server` (existing OSS, installable via pip or
Docker) as the sole execution backend. The Jupyter MCP Execution Gateway
component (DES-AIDS-004) wraps its tool calls and is the only code path
allowed to reach a kernel.

## Rejected alternatives / 却下した代替案
- Building a custom Jupyter MCP server: rejected as unnecessary duplication of
  an already-maintained OSS server; would delay MVP delivery without adding
  capability required by REQ-AIDS-003.
- Executing analysis code directly via a local Jupyter kernel client without
  MCP: rejected because it bypasses the MCP tool-call boundary the requirement
  and the skill's audit trail depend on.

## Consequences / 結果
The skill takes a hard runtime dependency on `jupyter-mcp-server` being
installed and reachable; REQ-AIDS-030 (MCP unavailability handling) exists
specifically to make that dependency's failure mode explicit and testable.
Version upgrades of `jupyter-mcp-server` must be tracked, since its tool
contract is load-bearing for every other component.
