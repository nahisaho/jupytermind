# ADR-0083: Model MCP server configuration as strictly validated managed-or-external entries

## Context / 背景
`DES-AISCI-011` (`REQ-AISCI-016`, `CHANGE-001`) must load MCP server
configuration before any connection or process startup happens. The design
problem is how strict that configuration contract should be: permissive
enough to defer interpretation until runtime, or explicit enough that bad
entries fail early with field-level diagnostics.

## Decision / 決定
`load_mcp_config(config_path)` reads JSON and validates each entry into one
of two dataclasses: `ManagedServerConfig{name, mode, launch_command,
endpoint_template, health_check_path}` or
`ExternalServerConfig{name, mode, endpoint}`. Managed entries must provide
`launchCommand`, `endpointTemplate`, and `healthCheckPath`, and both the
launch command and endpoint template must contain the literal `{port}`
placeholder so the process manager can substitute the chosen loopback port
consistently. External entries must provide an `endpoint`. Duplicate server
names and unsupported `mode` values are rejected immediately.

This makes configuration loading a discriminated-schema validation step,
not a loose dictionary pass-through. By the time any caller sees a returned
entry, it already has the fields and placeholder semantics needed by
`DES-AISCI-012` or `DES-AISCI-013`.

## Rejected alternatives / 却下した代替案
- **Deferring required-field checks until the server is first used**: rejected — that would mix configuration errors with connection/startup failures and violate the design requirement that validation finish before any server is started or connected to.
- **Using one untyped dictionary shape with many optional fields instead of mode-specific dataclasses**: rejected — callers would then need repeated defensive checks at every use site, and the code would no longer express the managed-versus-external split as a first-class API contract.
- **Representing managed servers with a fixed numeric port instead of `{port}` templates**: rejected — `DES-AISCI-012` chooses a free loopback port at runtime, so fixed-port configuration would either cause avoidable collisions or force a separate ad hoc endpoint-rewrite mechanism.

## Consequences / 結果
Future MCP configuration extensions must remain compatible with the
managed/external split and preserve fail-fast validation before runtime
use. Covered by the acceptance tests in `tests/test_ai_scientist_mcp.py`.
