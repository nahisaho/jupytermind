# ADR-0103: Resolve external estimators by cloning instances and calling factories, rejecting anything else, instead of a registry-style plugin interface (DES-AIDS-066)

## Context / 背景
`DES-AIDS-066` (REQ-AIDS-078) requires one resolver, used by `train_model`,
`tune_or_compare`, and `run_automl` alike, that turns a built-in
`model_name`, a caller-supplied estimator instance, or a caller-supplied
estimator factory into an estimator object for each fit, resolved freshly
whenever the resolver itself can guarantee freshness (built-in models and
cloned estimator instances). Cross-validation folds and AutoML/tuning
candidate comparisons each fit several independent model instances; reusing
one already-fitted external estimator *instance* object across folds/
candidates would silently leak trained state (e.g. a fitted
`RandomForestClassifier` reused across folds would not actually retrain on
each fold's data the way the built-in path does).

## Decision / 決定
`resolve_estimator` dispatches external input in `_materialize_external_estimator`
by shape, not by a registered plugin type: if the object already has both
`fit` and `predict` (an estimator instance), clone it via
`sklearn.base.clone` and, if `model_params` were also supplied, apply them
via `set_params` (raising `ValueError` if the cloned object lacks
`set_params`); otherwise, if the object is callable (a zero/kwarg-argument
factory), call it with `**model_params` and validate the *result* has `fit`
and `predict` before returning it as-is — the factory's return value is
*not* itself cloned, so freshness for the factory path is a caller
contract, not a resolver guarantee: a factory that returns the same
already-fitted singleton on every call would not be detected or corrected
here. Anything that is neither raises `ValueError`. `model_name`/built-in
resolution (`MODEL_BUILDERS` lookup, preserving existing hard-coded
defaults like `random_state=42`) runs only when `estimator is None`, so
external estimators always take precedence and never fall through to the
built-in branch.

## Rejected alternatives / 却下した代替案
- Requiring callers to always pass a zero-argument factory (never a
  pre-constructed instance), so every fit is guaranteed fresh by
  construction: rejected because it forces every caller to wrap an
  already-configured estimator instance in a trivial `lambda: estimator`
  just to satisfy the resolver, when `sklearn.base.clone` already gives an
  equivalent unfitted-copy guarantee for real estimator instances with less
  caller ceremony.
- A registered-plugin interface (e.g. callers implement a documented
  protocol class) instead of duck-typing on `fit`/`predict`/callability:
  rejected as unnecessary ceremony for this change's scope — scikit-learn's
  own ecosystem convention already treats "has `fit`/`predict`" as the
  estimator contract, and REQ-AIDS-078 only requires accepting
  sklearn-compatible external estimators, not a new plugin registration
  mechanism.

## Consequences / 結果
Every fit across `train_model`'s holdout and CV-fold paths, and every
candidate evaluated by `tune_or_compare`/`run_automl`, receives a
freshly-cloned estimator whenever the caller supplies an estimator
*instance* (or uses the built-in registry), with no cross-fold/
cross-candidate trained-state leakage for that path. Callers supplying a
*factory* instead are responsible for ensuring it returns a genuinely fresh
estimator on every call — the resolver validates only that the returned
object has `fit`/`predict`, not that it is unfitted or distinct from a
prior call's result; a factory that closes over and returns the same
fitted instance repeatedly will silently leak state across folds/
candidates, undetected by this resolver. An external estimator instance
that does not support `sklearn.base.clone` (e.g. an object holding
unpicklable/non-cloneable state) cannot be used directly; callers in that
situation must supply a factory instead, and must then uphold freshness
themselves. Any future pluggable-component resolver added to this package
should follow this same clone-instance-or-call-factory pattern, and should
likewise document that factory-returned freshness is a caller
responsibility rather than a resolver guarantee.
