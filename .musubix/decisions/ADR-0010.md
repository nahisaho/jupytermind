# ADR-0010: Bundle Japanese chart text support via the `japanize-matplotlib` package

## Context / 背景
REQ-AIDS-046 requires Japanese title/axis-label text in rendered charts to
display correctly instead of as "tofu" boxes (GitHub issue #32), and must
not depend on any font being pre-installed on the host.

## Decision / 決定
DES-AIDS-034 adopts the existing, widely used `japanize-matplotlib` PyPI
package, whose import side effect registers the bundled IPAexGothic
TrueType font with matplotlib's font manager. `render_chart` imports it
lazily (only when non-ASCII text is requested) and reasserts
`font.family` on every such call, rather than relying on a one-time,
process-global font registration that a caller's `plt.rcdefaults()` could
silently undo.

## Rejected alternatives / 却下した代替案
- Bundling our own font asset and registering it manually with matplotlib:
  rejected as unnecessary duplication of a maintained, already-redistributed
  package that solves the same problem.
- Eager, module-load-time `import japanize_matplotlib`: rejected because it
  would impose the package's import cost and deprecation warnings on the
  common ASCII-only path that never needs it.

## Consequences / 結果
Chart rendering gains a new runtime dependency (`japanize-matplotlib`).
Font configuration is no longer assumed to be sticky across calls; every
call that needs non-ASCII text re-asserts the font family explicitly.
