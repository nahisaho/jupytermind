# ADR-0067: Carry chart authoring metadata via a frozen dataclass plus a `bytes` subclass result type

## Context / 背景
`DES-AIDS-048` (REQ-AIDS-060, GitHub #35) addresses `render_chart`'s loss
of chart authoring metadata: it returns a bare `bytes` object, so the
title/axis-label/legend/missing-glyph information computed while
rendering a chart is discarded before `record_chart` (DES-AIDS-049) can
persist it for `notebook_audit`'s visual-audit checks.

## Decision / 決定
Introduce a frozen `ChartMetadata` dataclass bundling `title`, `xlabel`,
`ylabel`, `legend`, and `missing_glyphs`, and a `RenderedChart(bytes)`
subclass that carries a `chart_metadata: ChartMetadata` attribute plus
read-only forwarding properties for the same five fields. `render_chart`
returns `RenderedChart(png_bytes, chart_metadata=metadata)` instead of
plain `bytes`. Because `RenderedChart` is a true `bytes` subclass, every
existing caller using ordinary `bytes` operations (`base64.b64encode`,
equality, slicing, hashing) continues to work unmodified. (A later,
separate design extension additively adds a sixth `legend_title` field
and forwarding property to this same dataclass/subclass pair; this ADR
documents the original five-field decision scoped to REQ-AIDS-060.)

## Rejected alternatives / 却下した代替案
- **Returning a tuple `(bytes, ChartMetadata)` instead of a `bytes`
  subclass**: rejected — this is a breaking change for every existing
  `render_chart` caller that expects a `bytes`-shaped return value (e.g.
  direct base64-encoding or cell-output embedding), requiring a
  call-site rewrite across the repository for no behavioral benefit.
- **Attaching metadata as a module-level side-channel (e.g. a
  last-rendered-chart global)**: rejected — introduces hidden global
  state and a race/ordering hazard if `render_chart` is called multiple
  times before `record_chart` reads the side-channel; the result-object
  approach keeps metadata scoped to the specific call that produced it.
- **Mutating the caller-supplied `title`/`xlabel`/`ylabel` parameters in
  place to also carry the rendered axes' actual values**: rejected —
  these are plain `str | None` parameters, which Python cannot mutate
  in place at all, so this is not a viable mechanism; the actual
  competing option was requiring callers to pass a separate metadata
  argument at persistence time instead of attaching it to the return
  value, which was rejected because it would force every `record_chart`
  call site to be updated even though the metadata it needs is already
  fully determined by the preceding `render_chart` call.

## Consequences / 結果
Any future addition to the information `render_chart` must convey to
`record_chart` should extend `ChartMetadata`'s fields (with sensible
defaults to remain additive) rather than inventing a parallel side
channel. Covered by the REQ-AIDS-060 acceptance tests in
`tests/test_visualization.py`.
