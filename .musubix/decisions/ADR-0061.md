# ADR-0061: Explicit NaN guard ahead of significance branching in correlation interpretation

## Context / 背景
`DES-AIDS-055` (REQ-AIDS-067) addresses GitHub #47: when
`scipy_stats.pearsonr` returns `NaN` (e.g. a column has missing values),
`_interpret`'s existing significance-threshold comparison (`p_value >=
significance_threshold`) is always `False` for a NaN `p_value` in Python,
so control fell through to a confident, specific "weak ... correlation"
sentence that was spurious — the coefficient could not actually be
computed.

## Decision / 決定
Add an explicit `math.isnan(coefficient) or math.isnan(p_value)` guard
evaluated *before* the existing significance/magnitude branches, returning
a dedicated "correlation could not be computed" sentence (in both
supported languages) instead of a NaN-driven fallthrough. The numeric
`coefficient`/`p_value` fields returned by `correlation` are left
unchanged — only the generated interpretation text is affected — so
callers that inspect the raw numbers still see the actual NaN.

## Rejected alternatives / 却下した代替案
- **Relying on Python's NaN comparison semantics to "naturally" route to a
  safe branch**: rejected — this is the exact bug being fixed; NaN
  comparisons are always `False`, which silently selects the wrong branch
  rather than any explicit non-computable path.
- **Raising an exception when either value is NaN**: rejected as overly
  disruptive — `correlation` is expected to return a report object even
  for a statistically degenerate input (e.g. a column with excessive
  missing data); callers should receive a clear non-computable
  interpretation, not a crash.
- **Silently omitting the interpretation field for NaN cases**: rejected
  because an absent field is harder for a caller/report reader to
  distinguish from "not yet computed" than an explicit, worded statement
  that computation was impossible.

## Consequences / 結果
Any future numeric-result interpretation helper in `stats_analysis` that
can receive a NaN/undefined statistic from an underlying `scipy`/`numpy`
call must guard explicitly before any threshold comparison, since Python's
NaN comparisons silently evaluate `False` rather than raising. Covered by
the REQ-AIDS-067 acceptance tests in `tests/test_stats_analysis.py`.
