# ADR-0016: Shared pre-flight parameter validator instead of per-module ad hoc checks

## Context / 背景
REQ-AIMS-003 requires every module to reject a physically undefined or
numerically unstable parameter set before any simulation-state mutation.
Seven modules (REQ-AIMS-010 through 070) each define their own concrete
domain constraints (e.g., non-positive mobility, non-orthogonal
orientation matrix, undersized lattice).

## Decision / 決定
DES-AIMS-002 centralizes validation as a single shared
`validate_parameters(module_name, params)` function that every module
handler calls before any state mutation, returning a uniform
`{ok, parameter, constraint}` result. Each module registers its own
constraint table (the concrete numeric/domain rules from its own
requirement) with this shared validator rather than re-implementing ad hoc
`if` checks scattered through each module's run function.

## Rejected alternatives / 却下した代替案
- Per-module inline validation only (no shared validator): rejected
  because it would duplicate the "validate before any mutation" invariant
  seven times with no single place to audit or test it, increasing the
  risk that one module's TDD cycle accidentally skips a check.
- A generic JSON-Schema-based validator: rejected as unnecessary
  complexity; the constraints are simple scalar/array domain checks
  (positivity, orthogonality, shape) better expressed directly in Python
  against `pyproject.toml`'s existing numpy/scipy dependency set.

## Consequences / 結果
All seven modules depend on DES-AIMS-002 (see `Depends-On` in design.md);
a bug in the shared validator affects all modules uniformly, which is an
accepted trade-off for consistent, centrally testable REQ-AIMS-003
behavior.
