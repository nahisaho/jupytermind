# ADR-0069: Represent non-computable agreement rate as `None`, and exclude null-key rows via an eligibility pre-filter

## Context / 背景
`DES-AIDS-050` (REQ-AIDS-062, GitHub #36) addresses two related
`compare_datasets` defects: (1) a zero-eligible-row column reports a
misleading `agreement_rate == 1.0` instead of signaling "not computable",
and (2) null primary/candidate keys incorrectly compare equal under
Python tuple-set equality, so two unrelated rows that both have a `None`
key are miscounted as a matched key pair.

## Decision / 決定
Change `ColumnComparison.agreement_rate`'s type to `float | None`, using
`None` to mean "no eligible joined rows for this comparison" — an
intentional semantic extension existing and future consumers must handle
by branching on `None`. Before computing key sets, filter each side to
rows with no null key-column value (`dropna(subset=...)` on the full
row, preserving all non-key columns), deriving
`primary_key_values`/`candidate_key_values` and the inner-merge `merged`
frame from these filtered, non-null-key frames, so a null-key row can
never be counted as matched or unmatched, nor reach the per-column
comparison.

## Rejected alternatives / 却下した代替案
- **Keeping `agreement_rate: float` and reporting `0.0` for zero eligible
  rows**: rejected — `0.0` is indistinguishable from "every row
  disagreed," actively misleading callers into believing a comparison
  was performed when none was possible; `None` is the only
  non-ambiguous signal for "not computable."
- **Replacing null keys with a sentinel value (e.g. a fixed string) before
  the set/merge operations, instead of dropping those rows**: rejected —
  a single shared sentinel would cause every null-keyed row from primary
  to spuriously match every null-keyed row from candidate during the
  merge (the exact bug being fixed); this is the simplest, most direct
  approach that unconditionally satisfies REQ-AIDS-062's "null keys are
  never considered a match" acceptance without needing per-side
  non-colliding sentinel bookkeeping.
- **Filtering only the key-column projections (not the full row) before
  computing `primary_key_values`/`candidate_key_values`**: rejected — the
  per-column comparison's `merged` frame must also exclude null-key rows
  from its join, so filtering only the key-column projection and not the
  frame used for `merged` would leave the per-column agreement
  computation still including null-matched-null rows, reintroducing the
  bug for `agreement_rate` even after fixing `matched_keys`.

## Consequences / 結果
Any future consumer of `ColumnComparison.agreement_rate` must handle
`None` explicitly (e.g. in report rendering or downstream aggregation);
omitting a `None` branch will raise a `TypeError` on arithmetic rather
than silently misreporting. Covered by the REQ-AIDS-062 acceptance tests
in `tests/test_dataset_validation.py`.
