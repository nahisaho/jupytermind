# ADR-0125: Detect `propensity_score_match`'s logistic-fit non-convergence by catching `PerfectSeparationError` directly plus checking `mle_retvals["converged"]`, not by warning interception

## Context / 背景
REQ-AIDS-113 adds `ai_data_scientist.causal_inference.
propensity_score_match(covariate, treatment)`, which fits
`statsmodels.api.Logit(treatment, statsmodels.api.add_constant(
covariate)).fit(disp=0)` as its propensity-score model before greedy
nearest-neighbor matching. This is the same general problem ADR-0121
solved for `PHReg` (CHANGE-038/039's Cox regression): a statsmodels
optimizer can fail to converge on separable data, and the failure mode
must be detected reliably rather than silently returning an unbounded
or meaningless fit. Unlike `PHReg`, however, `statsmodels.api.Logit`'s
`.fit()` behaves differently on separation: for sufficiently severe
perfect separation it directly raises
`statsmodels.tools.sm_exceptions.PerfectSeparationError` from inside
`.fit()` rather than merely emitting a warning and returning a
finite-looking result, and `Logit`'s returned fit-result object *does*
expose a boolean convergence signal via `mle_retvals.get("converged")`
(unlike `PHReg`, which exposes no such attribute — the reason ADR-0121
had to rely on `ConvergenceWarning` capture instead). REQ-AIDS-113's own
Statement and Constraints already specify exactly this 2-condition
detection design: catching `PerfectSeparationError` directly, and
separately checking `mle_retvals.get("converged") is not True` on the
non-raising path, explicitly noting that any additional
`PerfectSeparationWarning`/`ConvergenceWarning` statsmodels may also
emit on that latter path is treated only as a converged-flag signal,
not as control flow via warning interception.

## Decision / 決定
Wrap the `statsmodels.api.Logit(...).fit(disp=0)` call in a `try`/`except
statsmodels.tools.sm_exceptions.PerfectSeparationError` block. If that
exception is raised, catch it and raise this module's own `ValueError`
naming `covariate`/`treatment` with the constraint "logistic fit did
not converge (data may be perfectly or quasi-separated)". If `.fit()`
instead returns a result object without raising, inspect that result's
`mle_retvals.get("converged")`; a value that is not exactly `True`
triggers the same `ValueError`. This is a 2-path check (raised
exception vs. non-`True` converged flag), consistent with ADR-0121's
established project pattern of treating statsmodels non-convergence as
a hard rejection rather than returning a partial/nonphysical propensity
score, but adapted to `Logit`'s own exposed signals (a named exception
plus a genuine `converged` attribute) rather than ADR-0121's
`ConvergenceWarning`-interception mechanism, which `PHReg` required only
because it exposes no `converged` flag of its own. Any
`PerfectSeparationWarning`/`ConvergenceWarning` statsmodels additionally
emits alongside a non-`True` `converged` flag is not separately
intercepted or required for detection — it is redundant with the
`converged` flag check REQ-AIDS-113 already specifies as authoritative.

## Rejected alternatives / 却下した代替案
**Reuse ADR-0121's `warnings.catch_warnings(record=True)` +
`simplefilter("always", ConvergenceWarning)` mechanism verbatim for
`Logit` as well**: rejected — `Logit`'s fit result already exposes a
genuine `mle_retvals["converged"]` boolean, unlike `PHReg`; relying on
warning capture when a direct, documented result-object attribute is
available would be an unnecessary indirection that REQ-AIDS-113's own
Constraints do not call for, and would miss the `PerfectSeparationError`
raise path entirely (that path does not return a result object to
inspect at all).
**Treat only a non-finite fitted coefficient as the non-convergence
signal, with no exception catch and no `converged`-flag check**:
rejected — a `PerfectSeparationError` raised by `.fit()` would propagate
as an unrelated, undocumented exception type to the caller instead of
this module's own named `ValueError`, and a `converged=False` result
can still carry finite-looking coefficients that would pass a naive
finiteness check, mirroring the exact gap ADR-0121 identified for
`PHReg`.
**Let any `PerfectSeparationWarning`/`ConvergenceWarning` drive control
flow via interception, as an alternative or addition to the
`converged`-flag check**: rejected per REQ-AIDS-113's own Constraints,
which state explicitly that such a warning "is not... control flow via
warning interception" for this requirement — the `converged` flag is
the authoritative signal on the non-raising path.

## Consequences / 結果
`propensity_score_match` never proceeds to greedy matching on a
non-convergent fit: either a raised `PerfectSeparationError` or a
`converged` flag that is not exactly `True` short-circuits the call
with this module's own named `ValueError` before any propensity score
or match pair is computed or returned. This detection depends on
`statsmodels.api.Logit` continuing to populate `mle_retvals["converged"]`
and to raise `PerfectSeparationError` for its current documented
separation cases; should a future statsmodels release change either
signal, this design would need re-verification, the same caveat
ADR-0121 already documents for `PHReg`'s `ConvergenceWarning`-based
mechanism.
