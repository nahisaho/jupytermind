# ADR-0092: Direct SciPy paired-test dispatch for `evaluate_experiment` (DES-AIDS-067)

## Context / 背景
`DES-AIDS-067` (REQ-AIDS-079, REQ-AIDS-080) requires `evaluate_experiment` to
support paired significance tests (`test="paired_t"`, `test="wilcoxon"`) over
aligned control/treatment rows or folds, without changing the pre-existing
`test="ttest"` independent two-sample path. Prior to CHANGE-010, callers
comparing paired observations (for example, the same validation rows scored
by two models) had to misuse `test="ttest"`'s independent two-sample test,
which does not account for the pairing and can misstate significance.

## Decision / 決定
Dispatch `test="paired_t"` directly to `scipy.stats.ttest_rel(control,
treatment)` and `test="wilcoxon"` directly to `scipy.stats.wilcoxon(control,
treatment)` (`_run_paired_test` in `experiment_evaluation.py`), after
`_validate_paired_inputs` rejects unequal-length inputs, mismatched index
order, and non-finite values. `test="ttest"` keeps calling
`scipy.stats.ttest_ind(control, treatment)` unchanged
(`_run_independent_ttest`), so existing callers see no behavior change.

## Rejected alternatives / 却下した代替案
- A new standalone paired-comparison function/module instead of extending
  `evaluate_experiment`'s `test` parameter: rejected because it would create
  two discoverable entry points for experiment comparison, increasing the
  risk that callers keep misusing the independent-samples path for paired
  data; a single dispatch point with an explicit `test` value is more
  discoverable and keeps one shared result contract (`ExperimentResult`,
  see ADR for DES-AIDS-069).
- A custom paired-test implementation instead of SciPy's `ttest_rel`/
  `wilcoxon`: rejected because SciPy's implementations are already
  well-tested, numerically stable, and are the same library already used by
  the pre-existing `ttest_ind` path, so there is no architectural reason to
  depart from it.

## Consequences / 結果
Callers must supply `control`/`treatment` with identical index order and
only finite numeric values for the paired paths, or `_validate_paired_inputs`
raises `ValueError`; this is intentionally stricter than the legacy
`test="ttest"` path, which performs no such alignment validation. Any future
paired-test addition (e.g. a permutation test) should reuse
`_validate_paired_inputs` for consistency unless a new ADR documents a
deliberate departure.
