# ADR-0109: Standalone YAML-based SKILL.md frontmatter parser for description-length guard

## Context / 背景
Issue #71 found that `tech-writer`'s `SKILL.md` `description` frontmatter
field (~1,817-1,884 characters) silently exceeds GitHub Copilot CLI's
1,024-character skill-description limit, causing the skill to be dropped
from discovery with no error. A regression test is needed to measure the
true parsed `description` length for `tech-writer` and, to prevent
recurrence, for every other bundled skill's `SKILL.md` as well.

An existing parser, `ai_data_scientist.skill_packaging.load_skill_manifest`
(REQ-AIDS-012), already extracts `name`/`description`/section headings from
a `SKILL.md`, but its frontmatter field regex
(`^(\w+):\s*"?(.*?)"?\s*$` with `re.MULTILINE`, no `re.DOTALL`) only
captures the first physical line following `description:` — it cannot
reconstruct a multi-line YAML folded (`>-`) scalar into the single string
Copilot CLI's loader actually sees, so it would undercount `description`
length for any skill using a folded scalar, including `tech-writer` (the
one affected by issue #71); not every bundled skill uses a folded
description (some use a single quoted inline value), but any skill whose
description is long enough to need folding is exactly the case this guard
exists to catch correctly.

## Decision / 決定
Add a new, standalone frontmatter parser (`DES-TECHWRITER-001`) that uses
Python's `yaml.safe_load` on the `---`-delimited frontmatter block, so the
returned `description` string is the exact value Copilot CLI's YAML-based
loader would parse, with no custom line-joining logic to maintain or get
wrong. This parser is not tied to any one skill's package (unlike
`ai_data_scientist.skill_packaging`, which is scoped to `ai-data-scientist`)
so it can be reused to check every `.github/skills/*/SKILL.md` file.

## Rejected alternatives / 却下した代替案
Reusing/patching `ai_data_scientist.skill_packaging.load_skill_manifest` in
place: rejected because that module is documented and tested
(`REQ-AIDS-012`, `tests/test_skill_packaging.py`) as parsing
`ai-data-scientist`'s own manifest specifically; broadening its regex-based
parser to handle YAML folded scalars correctly for all skills would
duplicate what a real YAML parser already does safely, and risks silently
changing `REQ-AIDS-012`'s existing behavior/evidence for an unrelated
feature.
Hand-rolled line-joining via regex (keep extending the existing approach):
rejected because YAML folded-scalar semantics (blank-line-preserves-newline,
trailing `-` strips final newline, etc.) are non-trivial to reimplement
correctly, and a parsing bug here would defeat the very regression guard
this change exists to add.

## Consequences / 結果
Any future bundled skill's `SKILL.md` is automatically covered by the new
repository-wide regression test without additional wiring, since the test
enumerates `.github/skills/*/SKILL.md` directly rather than listing skills
by name. `ai_data_scientist.skill_packaging.load_skill_manifest` is left
unchanged and keeps serving `REQ-AIDS-012` exactly as before.
