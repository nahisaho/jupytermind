# ADR-0064: Reuse the existing non-heading insight-candidate heuristic on heading-stripped text

## Context / 背景
`DES-AIDS-058` (REQ-AIDS-070) addresses GitHub #43:
`_looks_like_insight_candidate` unconditionally excluded any
heading-prefixed cell lacking an evidence fence from insight-candidacy,
even when the text following the heading stated a clear numeric
conclusion that would otherwise qualify.

## Decision / 決定
Strip every leading heading line (and the blank lines directly between
consecutive heading lines) from a heading-prefixed cell, then apply the
*same* existing non-heading candidacy heuristic to whatever text remains,
rather than introducing new, broader candidacy criteria. An empty
remainder (a heading-only cell) is never a candidate, preserving prior
behavior for pure section headers like "## 結果".

## Rejected alternatives / 却下した代替案
- **A new, separate heading-aware candidacy heuristic**: rejected —
  reusing the already-established non-heading heuristic on the stripped
  remainder keeps exactly one candidacy definition in the codebase, and
  REQ-AIDS-070/GitHub #43 describe this gap as a scope-narrowing fix, not
  a request for new candidacy criteria.
- **Treating any heading-prefixed cell as a candidate unconditionally**:
  rejected because it would reintroduce false positives for genuinely
  empty section-heading cells, which existing tests (GitHub #30's prior
  fix) explicitly guard against.
- **Only stripping a single leading heading line (not consecutive
  heading lines)**: rejected as insufficiently general — multi-level or
  consecutive heading markup (e.g. a heading followed immediately by a
  sub-heading before the body) would otherwise still be misclassified.

## Consequences / 結果
Any future insight-candidacy refinement should continue to route through
this single shared heuristic rather than branching into a parallel
heading-specific decision path, to avoid the two definitions drifting
apart. Covered by the REQ-AIDS-070 acceptance tests in
`tests/test_notebook_audit.py`.
