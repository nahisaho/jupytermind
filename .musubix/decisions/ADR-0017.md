# ADR-0017: Three-key (metadata/parameters/arrays) evidence schema instead of a flat result dict

## Context / 背景
REQ-AIMS-004 requires reproducible run evidence that can mix JSON-safe
scalar metadata (module name, unit system, schema version, seed) with
numpy numeric arrays, and REQ-AIMS-005 requires every module's evidence to
name its unit system. An earlier draft of REQ-AIMS-004 used a single flat
dict of float64 arrays, which could not represent a string `unit_system`
or an integer/`null` seed without breaking array-equality checks.

## Decision / 決定
DES-AIMS-003 records every run in-memory as exactly three top-level keys:
`metadata` (JSON-safe dict with `module`, `unit_system`, `schema_version`,
`seed`), `parameters` (JSON-safe dict of resolved inputs), and `arrays`
(dict of named `numpy.ndarray` values). For persistence, a separate
`to_json`/`from_json` pair encodes each `arrays` entry as an explicit
`{dtype, shape, data}` codec (data as a nested row-major JSON array) and
reconstructs it via `numpy.array(data, dtype=dtype).reshape(shape)`.
Reproducibility is checked only on the in-memory `arrays` via
`numpy.array_equal`, never on `metadata`/`parameters`, and must hold
through a `to_json`/`from_json` round trip.

## Rejected alternatives / 却下した代替案
- A single flat dict requiring every value to be a `float64` numpy array:
  rejected because it cannot hold a string unit-system label or an
  optional integer seed without an awkward encoding, and was flagged as
  self-contradictory in rubber-duck review.
- Separate sibling files (one JSON for metadata, one `.npz` for arrays):
  rejected as unnecessary filesystem complexity for the stated
  "re-loadable" requirement; a single `to_json`/`from_json` pair with an
  explicit ndarray codec is simpler to test and serialize.
- Claiming the in-memory `RunRecord` itself is directly JSON-serializable:
  rejected after rubber-duck review found this self-contradictory, since
  a `numpy.ndarray` is not JSON-serializable; the design instead
  distinguishes the in-memory record from its JSON-safe encoding.

## Consequences / 結果
Every module's run-evidence consumer must know to look for seeds/units in
`metadata` rather than alongside the arrays; this is a fixed, documented
contract applied uniformly by DES-AIMS-003, consistent with REQ-AIMS-004's
acceptance criteria.
