# ADR-0074: Reuse ai-data-scientist project resolution as the canonical workspace authority

## Context / 背景
`DES-AISCI-002` (`REQ-AISCI-002`, `REQ-AISCI-003`, `CHANGE-001`) defines how
`ai-scientist` decides whether a project name is valid and where its durable
workspace lives. The trade-off is between inventing a new ai-scientist-specific
naming/path contract versus reusing the already-governed `ai_data_scientist`
project layout while still adding ai-scientist's own phase directories.

## Decision / 決定
`resolve_research_project(name, projects_root=None)` performs one defensive
`isinstance(name, str)` type guard that raises `InvalidProjectNameError`
before calling into upstream validation. This is an intentional divergence
from pure delegation: without this guard, a non-string `name` would reach
`ai_data_scientist.project_manager.resolve_project(...)`'s
`_SLUG_PATTERN.match(name)` call and raise an unrelated `TypeError` instead
of the documented `InvalidProjectNameError`, so ai-scientist adds this
narrow type-check solely to normalize the error type for non-string input.
All substantive name-shape/content validation (slug rules, length, reserved
names, etc.) for actual string inputs remains exclusively
`ai_data_scientist.project_manager.resolve_project(...)`'s responsibility;
ai-scientist adds no independent content-validation policy for strings.
After that guard, `_ensure_phase_dirs(...)`
creates the seven ai-scientist subdirectories and returns a frozen
`ResearchProjectHandle` carrying `name`, `root`, and `notebook_path` copied
verbatim from ai-data-scientist's `ProjectHandle`, plus
`planning_dir`, `literature_dir`, `design_dir`, `manuscript_dir`,
`review_dir`, `reproducibility_dir`, and `presentation_dir`.

This preserves one stable workspace root and notebook path across both
features while keeping ai-scientist's added directories idempotent via
`mkdir(parents=True, exist_ok=True)`. The resolver therefore remains safe
across process-working-directory changes and does not introduce a second
naming regex or parallel path computation algorithm.

## Rejected alternatives / 却下した代替案
- **Maintaining an independent ai-scientist project-name regex and root-path calculation**: rejected — it would let `ai-scientist` accept or reject names differently from `ai-data-scientist`, breaking the explicit requirement that both features share the same stable project identity and notebook location.
- **Keeping only the upstream `ProjectHandle` and recomputing ai-scientist phase directories ad hoc in each phase module**: rejected — it would scatter path derivation across handlers, make the interface less precise than the documented `ResearchProjectHandle`, and invite subtle divergence in where phases write artifacts.
- **Creating phase directories lazily in whichever handler touches them first**: rejected — first-use behavior would then depend on which phase ran first, whereas `DES-AISCI-002` requires the research workspace to become complete and idempotent as soon as the project handle is resolved.

## Consequences / 結果
Any future change to project naming or root-path semantics must be made in
`ai_data_scientist.project_manager.resolve_project(...)` or stay compatible
with it; ai-scientist remains a strict extension of that contract. Covered
by the acceptance tests in `tests/test_ai_scientist_project_handle.py`.
