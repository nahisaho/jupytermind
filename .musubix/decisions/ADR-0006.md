# ADR-0006: GiNZA (ja_ginza) as the Japanese NLP pipeline

## Context / 背景
REQ-AIDS-023 requires Japanese text analysis (tokenization, POS tagging) as
part of the ML extension. The user explicitly specified
https://megagonlabs.github.io/ginza/ (GiNZA) as the required pipeline
rather than leaving the NLP backend open-ended.

## Decision / 決定
Use the GiNZA spaCy pipeline via its pinned `ja_ginza` model as the sole
Japanese NLP backend for REQ-AIDS-023. Acceptance criteria are defined
relative to this pinned model's output so results are deterministic and
reproducible across runs and environments.

## Rejected alternatives / 却下した代替案
- Bare MeCab/Sudachi without a higher-level pipeline: rejected because it
  would require building tokenization-to-linguistic-feature mapping
  ourselves, duplicating what GiNZA already provides via spaCy's Doc/Token
  API.
- Generic multilingual spaCy pipelines (e.g. `xx_ent_wiki_sm`): rejected for
  Japanese specifically because they do not match the accuracy or
  linguistic annotation depth GiNZA provides for Japanese, and the user
  explicitly requested GiNZA.

## Consequences / 結果
The ML extension takes a hard dependency on `ginza`/`ja_ginza` (and
therefore spaCy) for REQ-AIDS-023 only; REQ-AIDS-026 (non-Japanese text)
uses a separate, independently swappable NLP pipeline so a future change to
either language path does not ripple into the other.
