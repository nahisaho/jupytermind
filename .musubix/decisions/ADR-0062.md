# ADR-0062: Use csv.Sniffer with a fixed comma/tab/semicolon delimiter set and fallback warning

## Context / 背景
`DES-AIDS-056` (REQ-AIDS-068) addresses GitHub #42: `ingestion.ingest`'s
CSV branch unconditionally assumed a comma delimiter, so a tab- or
semicolon-separated `.csv` file was silently read as a single column with
no indication anything was wrong.

## Decision / 決定
Sniff the delimiter from a bounded text sample using the standard
library's `csv.Sniffer().sniff(sample, delimiters=",\t;")` before calling
`pandas.read_csv`. On success, pass the sniffed delimiter through
explicitly. On `csv.Error` (ambiguous sample), keep the existing
comma-default `read_csv` call unchanged, but append a mismatch warning to
a new `IngestionResult.warnings` field when the fallback produced exactly
one suspiciously-named column (header containing a literal tab or
semicolon) — never for a genuinely single-column file. The delimiter set
considered is deliberately fixed to the three named in REQ-AIDS-068, not
user-configurable.

## Rejected alternatives / 却下した代替案
- **A hand-written delimiter-frequency heuristic** (e.g. counting commas
  vs. tabs vs. semicolons per line): rejected because `csv.Sniffer` is the
  standard library's purpose-built, already-tested solution to exactly
  this problem; reimplementing it would duplicate logic for no behavioral
  gain and risk subtly different edge-case handling.
- **Always failing/raising when sniffing is ambiguous**: rejected as too
  disruptive — many genuinely single-column or atypically-formatted CSVs
  sniff ambiguously but parse correctly under the comma default; the
  existing fallback behavior must be preserved, only augmented with a
  warning when there's concrete suspicious evidence (a column name
  containing a delimiter character).
- **An open-ended user-configurable delimiter list**: rejected as out of
  scope — REQ-AIDS-068 names exactly comma/tab/semicolon as the problem's
  scope; broader configurability is a separate, unrequested feature.

## Consequences / 結果
Any future ingestion-format-detection need should default to a standard-
library sniffing/detection primitive before a hand-written heuristic,
matching this precedent. `IngestionResult.warnings` is now an established
extension point for non-fatal, evidence-based ingestion caveats. Covered
by the REQ-AIDS-068 acceptance tests in `tests/test_ingestion.py`.
