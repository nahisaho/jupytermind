# ADR-0065: Persist chart metadata on the image output itself via a shared helper

## Context / 背景
`DES-AIDS-059` (REQ-AIDS-071) addresses part of GitHub #40:
`build_image_output` never attached chart metadata to the output node it
built; only `record_chart` separately set cell-level metadata, so an
officially-rendered chart's image output carried no output-level record of
its own chart metadata, and multiple images in one cell could not be
disambiguated from output-level data alone.

## Decision / 決定
Extract the title/xlabel/ylabel/legend/missing_glyphs dict shape that
`record_chart` (`DES-AIDS-049`) already builds into a shared,
module-private `_chart_metadata_dict(chart_metadata) -> dict` helper, and
have `build_image_output` call it and attach the result as
`metadata={"chart": ...}` on the `nbformat.v4.new_output(...)` node it
returns whenever its `png_bytes` argument is actually a `RenderedChart`
(plain `bytes` input keeps empty metadata, unchanged). `record_chart`
itself needs no behavior change — it already calls `build_image_output`
and now benefits from output-level metadata "for free" through the shared
helper.

## Rejected alternatives / 却下した代替案
- **Duplicating the metadata-dict-building logic directly inside
  `build_image_output`**: rejected — `record_chart` already built this
  exact shape; duplicating the field list would create two places that
  must be kept in sync for the same five fields, a maintenance risk for
  no benefit over extracting one shared helper.
- **Changing `build_image_output`'s public signature to accept metadata
  explicitly**: rejected because `png_bytes` already carries the
  `RenderedChart` wrapper whenever metadata is available; adding a second
  parameter would require every call site to pass redundant information
  already present in its first argument.
- **Setting only cell-level metadata (status quo) and resolving
  per-image ambiguity some other way**: rejected — output-level metadata
  is the only way to attribute metadata to a specific image when a cell
  contains more than one chart output, which is exactly the limitation
  `DES-AIDS-060` needs resolved on the audit side.

## Consequences / 結果
Any future chart-metadata field added to `ChartMetadata` must be added to
the single shared `_chart_metadata_dict` helper so both `record_chart`'s
cell-level metadata and `build_image_output`'s output-level metadata stay
in sync automatically. Covered by the REQ-AIDS-071 acceptance tests in
`tests/test_visualization.py`.
