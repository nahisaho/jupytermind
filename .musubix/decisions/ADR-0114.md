# ADR-0114: Deploy `.github/skills` and verify Python modules from `npx jupytermind setup`, with an all-or-nothing containment-checked preflight

## Context / 背景
CHANGE-030 renamed the npm bootstrap package to `jupytermind` and verified
that `npm install jupytermind` correctly packs all 9 non-`sdd-*` skills
plus their Python modules into `node_modules/jupytermind/`. However,
nothing ever copies those skills out of `node_modules/jupytermind/.github/
skills/` into the consuming project's own `.github/skills/` directory,
which is the only location GitHub Copilot actually reads skills from. A
user who ran `npm install jupytermind` found the skills simply did not
become usable in their project — a genuine functional gap, not merely a
documentation or reporting issue.

During requirements authoring (REQ-AIDS-097) and 4 rounds of rubber-duck
review, several real safety hazards were identified for any
copy-into-consumer-project operation: (1) a naive single real-path check
on the destination parent fails outright against a clean project where
`.github/skills` does not exist yet; (2) checking each skill's
destination for a symlink-escape interleaved with copying it risks
destroying an earlier, already-processed skill (including any local
modifications) before a later skill's escape is discovered; (3) a
containment check against the project's cwd alone is insufficient if an
intermediate ancestor (e.g. `.github`) is itself a symlink — writes could
land outside the project before the final destination is ever checked;
(4) a containment check that only verifies "under cwd" (not "under the
specific already-validated `.github/skills` real path") admits an
in-cwd-but-still-wrong redirection target for all 9 skills collectively.

## Decision / 決定
1. Add a `"jupytermind"` entry to `package.json`'s `bin` map, pointing at
   the same `bin/ai-data-scientist.js` script as the existing
   `"ai-data-scientist"` entry. Both command names remain fully supported
   (no deprecation of the original), satisfying the user's explicit ask
   for `npx jupytermind setup` while preserving backward compatibility —
   there is exactly one implementation file to maintain.
2. Extend `bin/ai-data-scientist.js`'s existing `setup` dispatch path (not
   any other subcommand) with two new steps that run after the existing
   `ensureSetup()` venv/pip-install call: `deploySkills()` and
   `verifySkillPythonModules()` (see DES-AIDS-095 for full behavior).
3. `deploySkills()` uses a fixed 9-name allowlist
   (`ai-data-scientist`, `ai-chemistry-scientist`,
   `ai-genomics-scientist`, `ai-materials-scientist`,
   `ai-structural-biology-scientist`, `ai-scientist`, `tech-writer`,
   `japanese-prose`, `presentation-planner`) — never a `sdd-*`-prefix
   exclusion rule — so a future `sdd-*`-named skill directory added under
   `.github/skills` is never deployed to a consumer project unless
   explicitly added to this array.
4. Path safety is enforced in two phases, both using OS-level
   `fs.realpathSync.native` resolution and path-component-aware (never
   bare string-prefix) containment checks: first, `.github` then
   `.github/skills` are each individually created-if-missing and
   containment-verified one path segment at a time (verifying each
   already-existing ancestor before creating anything beneath it, so an
   outward-symlinked `.github` is caught before any write occurs beneath
   it even though `.github/skills` itself does not yet exist); second,
   once `.github/skills`'s own real path is fixed as the canonical
   "skills-root," all 9 prospective destination paths are checked for
   containment within that specific skills-root (not merely "under cwd"
   generally, which would wrongly admit an in-cwd redirection to an
   unrelated directory). All 9 checks must pass before any of the 9
   destinations is removed or copied — the preflight loop contains no
   destructive filesystem call, guaranteeing a failure on skill 9 never
   destroys skills 1 through 8.
5. Once preflight passes, each destination that already exists is removed
   entirely (`fs.rmSync` with `recursive: true, force: true`) and then the
   corresponding packaged source directory is recursively copied with
   `fs.cpSync`, guaranteeing an exact post-copy tree match (no stale
   leftover files) and a fully reproducible always-overwrite policy, as
   the user explicitly confirmed during intake.
6. `verifySkillPythonModules()` runs the venv's Python interpreter with an
   `import` statement for all 6 application modules the 9 skills'
   documented entry points depend on
   (`ai_data_scientist`, `ai_chemistry_scientist`, `ai_genomics_scientist`,
   `ai_materials_scientist`, `ai_structural_biology_scientist`,
   `ai_scientist`), reusing the existing `run()` helper so a nonzero exit
   is already handled by `main()`'s existing top-level error path with no
   new error-handling code.

## Rejected alternatives / 却下した代替案
**A separate `npx jupytermind install-skills` subcommand, distinct from
`setup`**: rejected because it adds a second onboarding step a user could
easily skip or forget, defeating the purpose of fixing the reported gap;
folding skill deployment into the existing `setup` command (the explicit
onboarding entrypoint every README/doctor flow already directs users to
run) guarantees deployment happens whenever a user actually sets up the
package, without requiring a second command to remember. This is
distinct from `ensureSetup()`'s own unconditional venv/pip-install call,
which runs for every subcommand (including non-`setup` ones) and is left
unchanged; `deploySkills()`/`verifySkillPythonModules()` run only on the
`setup` dispatch path, not on every invocation.

**Deriving the allowlist by filtering out any directory name starting
with `sdd-`**: rejected in favor of an explicit fixed allowlist. A
prefix-exclusion rule is defensive but untestable against the real
package today (its `files` array never contains an `sdd-*` entry), and
more importantly it fails open: any future non-`sdd-*`-named internal
tooling directory accidentally added under `.github/skills` would be
silently deployed to every consumer project. An explicit allowlist fails
closed instead — a new skill must be deliberately added to the array
before it is ever shipped to consumer projects.

**A single real-path check on the final destination parent, performed
once up front**: rejected because it cannot handle the clean-install
scenario (no pre-existing `.github/skills` directory) without either
failing outright (nothing to resolve yet) or silently skipping the check
for not-yet-existing paths (reintroducing the escape risk once the
directory is later created). The two-phase create-then-verify,
verify-all-then-destroy sequence was adopted instead, closing both gaps
identified across 4 rounds of rubber-duck review.

**Per-skill check-then-copy interleaved in a single loop**: rejected
because a symlink-escape discovered on, say, the 6th of 9 skills would
leave the first 5 already overwritten — a partial, non-atomic, and
potentially destructive outcome for a user's local modifications to
those earlier skills. Splitting into a full preflight loop (no
destructive calls) followed by a separate copy loop (only entered after
every check passes) makes the operation effectively atomic from the
perspective of "no skill is ever touched unless all 9 are known-safe."

## Consequences / 結果
`npx jupytermind setup` (and its `npx ai-data-scientist setup` alias)
becomes the single command that makes the npm package's skills and their
Python dependencies actually usable in a consumer project, closing the
reported gap. The fixed allowlist means adding a 10th skill to the
repository in the future requires updating `SKILL_ALLOWLIST` in
`bin/ai-data-scientist.js` alongside `package.json`'s `files` array (two
places to update, not one) — an accepted, explicit trade-off in favor of
fail-closed safety over fail-open convenience. The all-or-nothing
preflight adds a small amount of up-front filesystem-walk cost (bounded
by 9 skills plus a handful of ancestor directories) before any copy
begins, which is negligible relative to the existing venv/pip-install
cost `ensureSetup()` already incurs on a cold run.
