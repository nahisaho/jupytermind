# ADR-0119: ACMG/AMP classifier resolves simultaneous pathogenic-side and benign-side rule matches as `"uncertain_significance"` / `"conflicting_criteria"`, a documented extension beyond the published guideline

## Context / 背景
REQ-AGENOM-090 implements the Richards et al. (2015) ACMG/AMP Table 5
combining rules as a deterministic rule engine over caller-supplied
criterion codes. The published guideline defines, for each of the 5
classification tiers, a set of criterion-count combining rules, but it
does not explicitly state what a conformant implementation should do
when a `criteria` list simultaneously satisfies at least one
pathogenic-side rule (`P`/`LP`) and at least one benign-side rule
(`B`/`LB`) — a case the guideline's authors leave to expert human
judgement rather than defining algorithmically. A deterministic,
offline rule engine with no human reviewer in the loop cannot defer to
expert judgement, so it must pick one documented, fixed behavior for
this case rather than silently returning whichever tier its internal
evaluation order happens to check first.

## Decision / 決定
When both a pathogenic-side rule (`P1`-`P8` or `LP1`-`LP6`) and a
benign-side rule (`B1`-`B2` or `LB1`-`LB2`) match the same `criteria`
list, report `classification="uncertain_significance"` and the
sentinel `matched_rule="conflicting_criteria"` (not the id of either
individually-matched rule, and not `null`), so a caller can
distinguish this case from the separate "no rule matched"
(`matched_rule=null`) case while still correctly landing on
`uncertain_significance` either way. REQ-AGENOM-090's Constraints
section documents, in exactly those words, that this specific
resolution is "one explicit non-guideline disambiguation ... since the
published guideline leaves that case to expert judgement" — making
clear to any reader of requirements.md or SKILL.md that this one rule
is this implementation's own documented choice, not a verbatim
reproduction of Richards et al. (2015) Table 5.

## Rejected alternatives / 却下した代替案
**Report whichever side's rule was found first by evaluation order
(pathogenic-side rules are checked before benign-side rules in this
engine's fixed order)**: rejected — silently preferring the
pathogenic-side classification on a genuine evidentiary conflict would
be the more clinically consequential of the two possible silent
mistakes (treating a conflicting variant as pathogenic rather than
flagging the conflict), and would misrepresent the implementation's own
fixed evaluation order as a clinical judgement it is not entitled to
make.
**Raise a validation rejection (`{ok: false}`) instead of returning a
classification**: rejected — the `criteria` list itself is entirely
valid input (28 well-formed, non-duplicate codes); the ambiguity is in
the clinical interpretation of that input, not a malformed request, so
REQ-AGENOM-003's validation-rejection contract does not apply here.
**Return `matched_rule=null` (indistinguishable from "no rule matched
at all")**: rejected — collapsing "both sides matched" and "neither
side matched" into the same `null` sentinel would destroy information
a caller needs (a conflicting-evidence case usually warrants a
different downstream follow-up than a no-evidence case), even though
both cases share the same `classification="uncertain_significance"`.

## Consequences / 結果
Every acceptance fixture and future regression test for REQ-AGENOM-090
must treat `matched_rule="conflicting_criteria"` as a third distinct
sentinel value alongside a genuine rule id and `null`. `SKILL.md` and
any user-facing documentation for this module must state, verbatim or
in close paraphrase, that this disambiguation is this implementation's
own addition and that the module's overall output "must not be
presented as an authoritative final classification" (already required
by REQ-AGENOM-090's Constraints), so a future reader does not mistake
`conflicting_criteria` for part of the published ACMG/AMP standard.
