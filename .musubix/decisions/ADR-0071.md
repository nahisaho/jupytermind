# ADR-0071: Widen the Japanese-font trigger with a dedicated Unicode-block predicate over plotted data, not the existing non-ASCII check

## Context / 背景
`DES-AIDS-052` (REQ-AIDS-064, GitHub #38) addresses `render_chart`'s
bundled-Japanese-font trigger only inspecting caller-supplied
`title`/`xlabel`/`ylabel` strings: Japanese text appearing only in
plotted data values, tick labels, legend entries, or pandas-auto-generated
axis labels (column names, index name) was missed, producing mojibake/
missing-glyph output for charts whose only Japanese content lives in the
data rather than the caller-supplied labels.

## Decision / 決定
Add a new `_contains_japanese(text)` predicate matching specific Unicode
blocks (Hiragana, Katakana, Katakana Phonetic Extensions, halfwidth
Katakana, CJK Symbols and Punctuation, CJK Unified Ideographs and
Extension A, CJK Compatibility Ideographs), applied to the selected
`x`/`y` column values, index values, legend-source column names, and
pandas-auto-generated axis-label sources. This new check is OR-combined
with the existing, unmodified `_contains_non_ascii(title/xlabel/ylabel)`
check, so the bundled font is applied whenever either condition is true,
and the pre-existing REQ-AIDS-046 acceptance (any non-ASCII caller label
triggers the font) is preserved unchanged.

## Rejected alternatives / 却下した代替案
- **Reusing the existing `_contains_non_ascii` predicate for plotted
  data instead of adding a narrower Japanese-specific predicate**:
  rejected per REQ-AIDS-064's explicit scoping to Japanese-derived
  plotted data — `_contains_non_ascii` would also trigger the bundled
  font for any non-Japanese non-ASCII data (e.g. accented Latin
  characters), which is a broader behavior change than this defect fix
  is scoped to make, and would risk unexpected font substitution for
  unrelated locales.
- **Always applying the bundled Japanese font unconditionally (removing
  the trigger check entirely)**: rejected — this would change rendering
  output for every chart regardless of language content, a far larger
  and unscoped behavioral change inconsistent with the narrow-bugfix
  nature of this defect (issue #38 is specifically about missed
  detection, not about removing detection).
- **Inspecting every column in the DataFrame regardless of whether it is
  selected for plotting by `x`/`y`**: rejected — an unselected column's
  content has no bearing on what will actually be rendered, and
  inspecting it would risk false-positive font triggers (and wasted
  computation) for columns never shown in the chart.

## Consequences / 結果
Any future trigger-condition change must keep the title/xlabel/ylabel
non-ASCII check and the plotted-data Japanese-block check as two
independently necessary, OR-combined conditions, and must continue
running before the figure is created (so DES-AIDS-048's plot/savefig
step observes the final, correctly configured font). Covered by the
REQ-AIDS-064 acceptance tests in `tests/test_visualization.py`.
