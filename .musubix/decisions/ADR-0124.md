# ADR-0124: Diagnose MCAR-inconsistency for REQ-AIDS-110 with a two-sample t-test (`scipy.stats.ttest_ind`) between missingness groups on one caller-supplied probe column, not Little's (1988) global MCAR chi-square test

## Context / 背景
REQ-AIDS-110 adds `ai_data_scientist.missing_data_analysis.
diagnose_missingness(target_column, probe_column)`, a heuristic
diagnostic that partitions one caller-supplied `probe_column` into two
groups by whether the corresponding `target_column` entry is missing
(`None`), and reports whether those two groups differ in `probe_column`
mean. The formal statistical literature on missing-data mechanisms
defines Little's (1988) global MCAR test, a joint chi-square test over
all variables' missingness patterns simultaneously, requiring multiple
candidate auxiliary variables, an estimated covariance structure across
them, and (for fully general use) an EM-based or multiple-imputation
estimation step. REQ-AIDS-110's own Statement and Constraints scope this
module to a single caller-supplied `probe_column` tested against one
`target_column`'s missing/observed split — a deliberately narrower
single-probe design, not a reimplementation of Little's global test.

## Decision / 決定
Implement the heuristic as specified in REQ-AIDS-110: split
`probe_column` into the "missing" group (rows where `target_column` is
`None`) and the "observed" group (rows where it is not), run
`scipy.stats.ttest_ind` (two-sample, equal-variance Student's t, the
library default) between those two groups, and report
`diagnosis="MCAR_inconsistent"` when `p_value < 0.05` (naming
`probe_column` as the associated column) or `"MCAR_consistent"`
otherwise, always accompanied by the fixed `note` string disclaiming
that this cannot confirm MAR and cannot detect or rule out MNAR. This
specific test choice follows directly from REQ-AIDS-110's own Statement
(a two-group mean-difference test over exactly one probe variable) and
Constraints (explicitly naming `scipy.stats.ttest_ind` and explicitly
contrasting this heuristic against "Little's (1988) formal MCAR
chi-square test" as the thing it deliberately is not): a two-sample
t-test is the minimal, standard, well-understood statistical procedure
for "does this one auxiliary variable's mean differ between two groups
defined by another variable's missingness", and is already available
via the project's existing `scipy` dependency with no new library
required.

## Rejected alternatives / 却下した代替案
**Implement Little's (1988) global MCAR chi-square test**: rejected for
this increment — it requires multiple simultaneously-modeled variables
and joint covariance/EM estimation, which is a materially larger
statistical and engineering scope than REQ-AIDS-110's single-probe-column
Statement and Constraints call for; REQ-AIDS-110 explicitly frames this
module as a heuristic proxy for, not a reimplementation of, that formal
test, and the required `note` field exists specifically so this
narrower scope is never silently presented as the formal test's
equivalent.
**Use a non-parametric two-group test (e.g. `scipy.stats.mannwhitneyu`)
instead of `ttest_ind`**: rejected as inconsistent with REQ-AIDS-110's
own Statement and Constraints, which explicitly name
`scipy.stats.ttest_ind` (equal-variance Student's t) as the designated
procedure; a rank-based alternative would also change the acceptance
fixture's exact `t_statistic`/`p_value` values that REQ-AIDS-110's
Acceptance already fixes empirically.
**Use Welch's unequal-variance t-test (`equal_var=False`) instead of the
default equal-variance Student's t**: rejected — REQ-AIDS-110 does not
call for per-group variance testing or an automatic equal/unequal
variance selection step, and introducing one would be an unrequested
scope addition beyond "the two-sample t-test (`scipy.stats.ttest_ind`,
equal-variance Student's t by default)" that the requirement's own
Constraints text specifies verbatim.

## Consequences / 結果
`diagnose_missingness` remains a single-probe, single-test heuristic by
design: a caller wanting evidence across multiple auxiliary variables
must call it once per candidate `probe_column` and interpret the
results jointly themselves; this module performs no multiple-comparison
correction across repeated probe-column calls (out of scope for this
increment). Because the mechanism is fixed to `scipy.stats.ttest_ind`,
the module introduces no new third-party dependency and its exact
acceptance-fixture values (`t_statistic=15.0`, `p_value≈3.85e-07` for
the documented fixture) remain stable and reproducible.
