# ADR-0035: RunRecord evidence schema retargeted to numpy/scipy provenance

## Context / 背景
REQ-AGENOM-004 needs a reproducible, JSON-safe run-evidence record for every genomics module invocation. The chemistry skill's accepted `RunRecord` schema (`{metadata, parameters, result}` with library-version provenance in `metadata`) already satisfies this shape; only the provenance fields differ (numpy/scipy versions instead of RDKit/scikit-learn versions).

## Decision / 決定
Reuse the `RunRecord` schema verbatim, with `metadata` always recording `module`, `schema_version`, `numpy_version`, and `scipy_version` — the last always present, even for the 4 modules whose own computation never calls scipy, so that every one of the 5 modules' run records is uniformly comparable under REQ-AGENOM-004.

## Rejected alternatives / 却下した代替案
Making `scipy_version` optional and recording it only for the one module that calls `scipy.stats.hypergeom.sf`: rejected during design review, because an optional field would make REQ-AGENOM-004's acceptance criterion (every module's run record carries `scipy_version`) ambiguous to verify mechanically, and would diverge from the uniform evidence contract the chemistry skill established.

## Consequences / 結果
All 5 genomics modules' run records are now mechanically comparable on the same fixed key set, simplifying any future cross-module evidence tooling.
