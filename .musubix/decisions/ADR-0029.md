# ADR-0029: Fixed criterion-check order and single-ordered-list violation reporting for ADMET heuristics

## Context / 背景
An initial REQ-ACHEM-020 draft specified Cyclosporine A's Lipinski and
Veber violations as two separate bracketed lists per rule ("naming exactly
`["MolWt"]` and `["NumHAcceptors"]`"), which rubber-duck review correctly
flagged as an ambiguous/impossible schema: a single `lipinski_violations`
field cannot be two different lists simultaneously, and implementers could
reasonably choose incompatible JSON shapes (e.g., one list vs. two).

## Decision / 決定
DES-ACHEM-020 evaluates the 4 Lipinski criteria in one fixed order
(`MolWt`, `MolLogP`, `NumHDonors`, `NumHAcceptors`) and the 2 Veber
criteria in one fixed order (`NumRotatableBonds`, `TPSA`), appending each
violated criterion's name to a single ordered `lipinski_violations` or
`veber_violations` list in that fixed check order. Cyclosporine A's fixed
acceptance fixture is therefore the single list
`lipinski_violations = ["MolWt", "NumHAcceptors"]` and
`veber_violations = ["NumRotatableBonds", "TPSA"]` — not two separate
lists.

## Rejected alternatives / 却下した代替案
- Two independent per-rule violation containers that could each hold
  multiple criteria (e.g., a dict keyed by criterion name): rejected as
  unrequested extra structure; a single ordered list in a fixed
  check-order is sufficient to deterministically test and report which
  criteria failed.
- Reporting violations in an unspecified/hash-map iteration order:
  rejected because that would make the acceptance fixture
  non-deterministic across Python versions/implementations; a fixed
  check-order list removes this ambiguity entirely.

## Consequences / 結果
Both the Lipinski and Veber evaluators in DES-ACHEM-020's implementation
must iterate their criteria in the exact fixed order documented in
REQ-ACHEM-020 and this ADR; reordering the check sequence later would be
a breaking change to the acceptance fixture and would require a new
requirement revision.
