# ADR-0088: Record phase evidence in an append-only project registry with per-file locking and atomic replacement

## Context / 背景
`DES-AISCI-016` (`REQ-AISCI-020`, `CHANGE-001`) provides the durable proof
store that all ai-scientist phases write through. The architectural choice
is how to persist evidence so concurrent writes and crashes do not corrupt
the registry, while keeping the read/query API simple enough for phase
gating and downstream manifest construction.

## Decision / 決定
Evidence is stored in one project-local JSON file,
`.ai_scientist_evidence.json`, represented as an ordered list of frozen
`EvidenceRecord{project, phase, artifact_path, artifact_kind, created_at,
metadata}` values. `record_evidence(...)` is the only append API: it derives
a path-specific lock via `_lock_for(...)`, reads existing records,
appends the new record, and persists the full list using `_write_records(...)`,
which writes to a `.tmp` sibling and atomically replaces the destination.
Read paths stay simple through `query_evidence(...)` and `latest_evidence(...)`.

This gives ai-scientist one durable, append-oriented evidence ledger shared
by all phase handlers, while still being robust against same-process
concurrency and mid-write interruption. The design keeps evidence storage
separate from lifecycle state so the same artifact record can serve gating,
delegation, and audit use cases.

## Rejected alternatives / 却下した代替案
- **Embedding evidence lists inside the phase-state file**: rejected — lifecycle transitions and artifact provenance evolve at different rates, and mixing them would make state writes larger, noisier, and more tightly coupled than the design requires.
- **Creating one standalone file per evidence artifact instead of a central registry**: rejected — phase-completion queries would then need directory scans and filename conventions rather than a direct, phase-scoped API with durable metadata.
- **Appending by naive in-place file writes without locking or atomic replace**: rejected — concurrent phase activity or a crash during write could lose records or leave malformed JSON, which directly violates the durability constraint.

## Consequences / 結果
Future phase handlers must continue to publish their artifacts through
`record_evidence(...)`, and registry format changes must preserve atomic
durability semantics. Covered by the acceptance tests in
`tests/test_ai_scientist_evidence_registry.py` and
`tests/test_ai_scientist_phase_state.py`.
