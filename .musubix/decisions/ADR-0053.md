# ADR-0053: Multiclass coefficient-magnitude aggregation for default explainability

## Context / 背景
`DES-AIDS-019`/`DES-AIDS-070` (REQ-AIDS-021, REQ-AIDS-082) require the default
`explain_model(..., method="default")` path to compute one scalar global
feature-importance value per feature even when the underlying model is a
multiclass linear model (for example `LogisticRegression` with
`multi_class="multinomial"`), whose `coef_` is a 2D array with one row per
class rather than one coefficient per feature. The pre-change implementation
only handled the single-output case (`coef_.shape == (n_features,)`) and
silently misbehaved (truncating or misaligning values) for the 2D case,
which is the defect reported in GitHub #58.

## Decision / 決定
Aggregate multiclass coefficient magnitudes as
`np.abs(coef_).mean(axis=0)` before pairing the resulting one-value-per-feature
vector with `feature_names`, and derive `ranking` by sorting those aggregated
values in descending order. `importance_kind` remains
`"coefficient_magnitude"` for both the single-output and multiclass cases, so
callers see one consistent contract regardless of class count.

## Rejected alternatives / 却下した代替案
- `np.abs(coef_).max(axis=0)` (worst-case per-class magnitude): rejected
  because it overweights a single class's view of a feature and does not
  represent the feature's overall global influence across all classes,
  which is what REQ-AIDS-021's "global feature-importance artifact" framing
  requires.
- L2 norm across classes (`np.linalg.norm(coef_, axis=0)`): rejected as an
  unnecessary departure from the existing "magnitude" semantics already
  documented for the single-output case; squaring/rooting would change the
  relative scale of `feature_importances` values between single-output and
  multiclass models for no behavioral benefit.
- Reporting one importance vector per class instead of a single aggregate:
  rejected because `ExplainabilityResult.feature_importances` is a flat
  `dict[str, float]` contract already relied on by existing single-output
  callers (REQ-AIDS-021 backward-compatibility constraint in DES-AIDS-070);
  introducing a per-class shape would be a breaking contract change outside
  this defect-fix's scope.

## Consequences / 結果
`DES-AIDS-019` and `DES-AIDS-070` both depend on this aggregation rule for
REQ-AIDS-021/REQ-AIDS-082 compliance. Any future model family with a
per-class coefficient matrix (for example multiclass linear SVM) should
reuse the same `mean(abs(coef_), axis=0)` rule for consistency unless a new
ADR documents a deliberate departure.
