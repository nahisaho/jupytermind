# ADR-0094: Extend `ExperimentResult` with an optional confidence interval instead of a new result type (DES-AIDS-069)

## Context / 背景
`DES-AIDS-069` (REQ-AIDS-079, REQ-AIDS-080, REQ-AIDS-081) requires a result
payload that keeps the existing `test="ttest"` caller contract unchanged
while also carrying the bootstrap confidence interval produced by
`DES-AIDS-068`. Before CHANGE-010, `ExperimentResult` had only `statistic`,
`p_value`, and `interpretation`, with no way to represent an interval
estimate that has no corresponding p-value.

## Decision / 決定
Add one optional field, `confidence_interval: tuple[float, float] | None =
None`, to the existing `ExperimentResult` frozen dataclass (`CODE-AIDS-101`),
instead of introducing a separate bootstrap-only result type. For `ttest`,
`paired_t`, and `wilcoxon`, `confidence_interval` stays `None` and
`statistic`/`p_value` keep their existing hypothesis-test meaning. For
`paired_bootstrap`, `statistic` holds the observed treatment-minus-control
difference, `confidence_interval` holds the bootstrap interval, and
`p_value` is set to `float("nan")` to signal explicitly that no p-value is
being claimed for this path. `_interpret_bootstrap_interval` is a separate
bilingual formatter from `_interpret`, so the bootstrap path's message never
uses hypothesis-test language ("statistically significant") that would not
apply to an interval estimate.

## Rejected alternatives / 却下した代替案
- A new `BootstrapExperimentResult` type returned only by
  `test="paired_bootstrap"`: rejected because `evaluate_experiment` has a
  single return-type contract today; introducing a second return type would
  force every caller to type-check or branch on the `test` argument's result
  shape, which is a larger compatibility-surface change than this
  change's scope (REQ-AIDS-079–081 are additive, not a contract redesign).
- Reusing `p_value=0.0` or `p_value=1.0` as a placeholder instead of `NaN`
  for the bootstrap path: rejected because either placeholder is a valid,
  misleading p-value that a caller could mistake for a real (in)significant
  hypothesis-test result; `NaN` makes the "no p-value" condition
  unambiguous and already propagates correctly through common numeric
  handling (e.g. `math.isnan`).

## Consequences / 結果
Existing `test="ttest"` callers that only read `statistic`/`p_value`/
`interpretation` are unaffected, since `confidence_interval` defaults to
`None` and the existing three fields keep their original position/meaning.
Any caller that wants the bootstrap interval must explicitly read
`confidence_interval` and must not treat `paired_bootstrap`'s `NaN`
`p_value` as a valid significance result. Any future experiment-test path
added to this module should prefer extending this shared result type over
introducing another parallel result type, unless a new ADR documents a
deliberate departure.
