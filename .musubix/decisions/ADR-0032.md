# ADR-0032: Fixed-formula pharmacophore-complementarity docking-score heuristic, not a physical docking simulation

## Context / 背景
REQ-ACHEM-050 needs a deterministic, locally-computable "docking score"
with no external docking engine (e.g., AutoDock Vina), no 3D conformer
generation, and no energy function — consistent with this skill's
no-network-call, no-external-solver-binary convention. A prior draft left
the scoring formula partly implicit in the Statement, which rubber-duck
review (and the EARS single-obligation validator) found both reduced
testability and violated the one-`shall`-per-Statement rule.

## Decision / 決定
DES-ACHEM-050 implements a fixed, simplified geometric/polar
complementarity heuristic: ligand volume is approximated as
`heavy_atom_count * 15.0` Å³ (a constant per-heavy-atom volume), compared
against the user-supplied pocket volume via `size_fit`; hydrogen-bond
donor/acceptor counts are matched against pocket site counts via
`hbond_fit`; the two sub-scores are averaged 50/50 into `score`. The exact
formulas are moved into REQ-ACHEM-050's Constraints field (and mirrored in
DES-ACHEM-050's Responsibilities) rather than the Statement, keeping the
Statement to a single observable obligation ("report a heuristic docking
score in [0, 1]"). Every output and SKILL.md documentation explicitly
labels this as a heuristic, not a physically accurate docking simulation.

## Rejected alternatives / 却下した代替案
- Integrating a real 3D-conformer-based energy scoring function (e.g., a
  simplified Lennard-Jones + electrostatics grid score): rejected as
  disproportionate scope for this increment and as implying a level of
  physical accuracy this heuristic does not have; it would also require
  3D conformer generation (`AllChem.EmbedMolecule`), adding
  nondeterminism risk (conformer generation can be seed-sensitive) that
  would conflict with REQ-ACHEM-004's determinism requirement unless a
  fixed seed were introduced — undesirable complexity for a heuristic
  module.
- Leaving the scoring formula entirely in the Statement: rejected because
  the EARS validator and rubber-duck review both flagged this as
  multiple obligations in one Statement; moving the formula to
  Constraints (cross-referenced from the design) resolved this cleanly,
  mirroring the pattern already used for REQ-AIMS-010's Constraints.

## Consequences / 結果
This module's score has no claim to physical/binding-affinity accuracy;
any future requirement for a physically grounded docking score would need
a new requirement (and likely a new, heavier dependency such as a real
conformer generator), not a revision of REQ-ACHEM-050.
