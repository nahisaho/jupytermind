# ADR-0113: Rename the npm bootstrap package to `jupytermind` and extend the skill-packaging completeness guard to ai-genomics-scientist, ai-materials-scientist, and ai-structural-biology-scientist

## Context / 背景
The repository's npm bootstrap package currently publishes under the name
`ai-data-scientist-skill`, a name chosen when the package shipped only the
`ai-data-scientist` skill. The repository (and its npm payload) has since
grown to include `ai-chemistry-scientist`, `ai-genomics-scientist`,
`ai-materials-scientist`, `ai-scientist`, `ai-structural-biology-scientist`,
`japanese-prose`, `presentation-planner`, and `tech-writer`. A user
attempting `npm install jupytermind` (the repository's own name) found no
such package exists; the only published name is
`ai-data-scientist-skill`, which under-represents the package's current,
much broader scope.

Separately, while investigating the rename, `npm pack --dry-run` revealed
that `package.json`'s `files` array is missing entries for 3 of the 5
`ai-*`-prefixed scientist skills: `ai-genomics-scientist`,
`ai-materials-scientist`, and `ai-structural-biology-scientist` are
present as skill directories and have dedicated `src/` Python modules, but
neither their `.github/skills/<name>` payload nor their
`src/<module>/**/*.py` sources are listed in `files`, so none of their
code ships in the packed npm artifact despite `ai-chemistry-scientist` and
`ai-scientist` (added by CHANGE-019/CHANGE-020/CHANGE-023) already being
correctly packaged. CHANGE-023 (DES-AISCI-020) previously added an
automated regression test
(`test_TEST_AISCI_048_npm_package_ships_skill_payloads_with_matching_python_sources`)
that proves consistency for skill entries already present in `files`, but
does not assert that every non-`sdd-*` skill directory is present in
`files` at all — so a wholly-missing skill entry (exactly this bug) is not
caught by the existing guard.

## Decision / 決定
1. Rename `package.json`'s `name` field from `ai-data-scientist-skill` to
   `jupytermind`, matching the repository name, and bump the version.
   The `bin` entry (`"ai-data-scientist": "bin/ai-data-scientist.js"`)
   is left unchanged — the CLI subcommand name is independent of the
   npm package name and nothing in the codebase or its tests binds them
   together. `README.md`/`README-ja.md` install instructions are updated
   from `npm install ai-data-scientist-skill` to `npm install
   jupytermind` (the only two call sites referencing the old package
   name, confirmed by repository-wide search).
2. Add the 3 missing `files` entries — `.github/skills/ai-genomics-scientist`,
   `.github/skills/ai-materials-scientist`,
   `.github/skills/ai-structural-biology-scientist`, and their matching
   `src/ai_genomics_scientist/**/*.py`, `src/ai_materials_scientist/**/*.py`,
   `src/ai_structural_biology_scientist/**/*.py` globs — bringing all 5
   `ai-*`-prefixed scientist skills to parity with `ai-chemistry-scientist`
   and `ai-scientist`.
3. Add DES-AGENOM-080, DES-AIMS-080, and DES-ASTRUCT-060 (REQ-AGENOM-080,
   REQ-AIMS-080, REQ-ASTRUCT-060), each a direct per-feature instance of
   DES-AISCI-020's existing npm skill-package completeness guard pattern
   (`loadPackageManifest`/`listPackedFiles`/assert-parity helpers already
   generalized in `src/ai_scientist/npm_packaging.py` by CHANGE-023), so
   each of the 3 newly-packaged skills gets its own automated proof that
   its skill payload and Python sources are both declared in `files` and
   actually present in the packed artifact.
4. Reuse (not duplicate) `src/ai_scientist/npm_packaging.py`'s existing
   generic helpers (`load_package_files`, `load_npm_pack_dry_run_paths`,
   `iter_skill_python_globs`) for all 3 new tests. Note that CHANGE-023's
   own `tests/test_ai_scientist_skill_packaging.py` predates this
   generalized module and still defines its own local
   `_load_package_files`/`_load_npm_pack_dry_run_paths` helpers rather
   than importing it; this ADR's new tests reuse the generalized module
   directly, and refactoring the CHANGE-023 test to do the same is left
   as an optional future follow-up, out of this change's scope.

## Rejected alternatives / 却下した代替案
**Publish a new `jupytermind` package alongside the existing
`ai-data-scientist-skill`** (dual-publish, keep both names forever):
rejected because it immediately creates two packages with diverging
version histories that must be kept manually synchronized on every
future release, for no benefit once the repository has a single
canonical name; a rename with the old name simply ceasing future
releases (optionally `npm deprecate`d by the user outside this change,
since that requires interactive npm authentication not available to this
automated workflow) is simpler and matches the user's explicit choice.

**Leave the package name as `ai-data-scientist-skill` and only fix the
missing `files` entries**: rejected because the user explicitly asked for
the rename to `jupytermind` as part of this change's scope; fixing only
the packaging gap would leave the original problem (`npm install
jupytermind` not working) unresolved.

**Write one combined test asserting every non-`sdd-*` skill directory is
present in `files`, instead of 3 separate per-feature tests**: considered,
but rejected as the primary mechanism in favor of keeping CHANGE-023's
established one-test-per-feature pattern (so each feature's own
requirements.md/design.md/test suite is self-contained and traceable via
its own `REQ-*`/`DES-*`/`TEST-*` IDs, consistent with every other
per-feature requirement in this repository). The underlying latent gap in
CHANGE-023's original test (it only checks consistency for already-present
entries, not wholesale absence) is still worth hardening, but doing so is
left as a general regression-test improvement rather than folded into
these feature-scoped `REQ-AGENOM-080`/`REQ-AIMS-080`/`REQ-ASTRUCT-060`
guarantees, to keep this ADR's scope limited to the reported gap.

## Consequences / 結果
- `npm install jupytermind` and `npm view jupytermind` resolve to this
  project once the renamed package is published via the existing
  `npm-publish.yml` GitHub Actions workflow (triggered by a new GitHub
  Release/tag, unchanged mechanism from CHANGE-019/CHANGE-020).
  `npm install ai-data-scientist-skill` continues to resolve to the last
  version published under that name (`0.2.5`) but receives no further
  updates.
- All 5 `ai-*`-prefixed scientist skills (`ai-chemistry-scientist`,
  `ai-data-scientist`, `ai-genomics-scientist`, `ai-materials-scientist`,
  `ai-structural-biology-scientist`) plus `ai-scientist` itself now ship
  their full skill payload and Python sources in the packed npm artifact,
  each proven by its own automated packaging-completeness test.
- A future new `ai-*` skill must add both its `files` entries and its own
  `REQ-*`/`DES-*` packaging-completeness requirement (following this
  ADR's and DES-AISCI-020's pattern) or risk silently shipping an
  incomplete package, exactly as happened here.
