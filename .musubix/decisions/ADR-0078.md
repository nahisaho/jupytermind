# ADR-0078: Keep manuscript drafting as a Markdown-first tech-writer delegation with explicit evidence manifest input

## Context / 背景
`DES-AISCI-006` (`REQ-AISCI-009`, `CHANGE-001`) governs how the
manuscript-writing phase turns prior research work into a manuscript while
keeping ai-scientist from becoming its own prose-generation system. The
concrete trade-off is whether to delegate only the writing act, or also to
let downstream format/rendering concerns distort that boundary.

## Decision / 決定
`write_manuscript(...)` builds a research evidence manifest by querying the
evidence registry and selecting only the planning, literature-review,
experimental-design, and data-analysis phases. It invokes the pinned
`tech-writer@0.3.0` dependency in `write` mode with a payload containing
the project identity, the triggering instruction, and that evidence
manifest, then writes the returned content to
`handle.manuscript_dir / "manuscript.md"`. Ai-scientist itself does not
synthesize manuscript prose; it supplies bounded project context and records
the resulting artifact.

This keeps the manuscript adapter focused on delegating a Markdown draft and
gathering the exact research evidence tech-writer needs. Format conversion,
if any, remains a separate `DES-AISCI-018` concern so the drafting adapter's
contract stays stable and independent of later rendering choices.

## Rejected alternatives / 却下した代替案
- **Requesting LaTeX or another final publication format directly from `tech-writer`**: rejected — the current sibling skill contract is Markdown-only, and coupling manuscript drafting to final rendering would violate the explicit separation between `DES-AISCI-006` and `DES-AISCI-018`.
- **Passing only the raw instruction and project name, without a structured evidence manifest**: rejected — that would discard the concrete artifacts produced by prior phases and make manuscript generation depend on less traceable prompt context instead of explicit, queryable evidence.
- **Implementing local summarization/prose assembly inside ai-scientist instead of delegating to `tech-writer`**: rejected — it would duplicate an already-governed writing capability and turn ai-scientist into the owner of manuscript prose quality, contrary to the design's single-responsibility split.

## Consequences / 結果
Future manuscript-writing changes must preserve the Markdown-first
delegation boundary and continue supplying explicit prior-phase evidence to
`tech-writer`. Covered by the acceptance tests in
`tests/test_ai_scientist_delegation.py`.
