# ADR-0118: PK non-compartmental analysis raises `ValueError` for a non-positive terminal elimination rate constant and breaks `tmax` ties by first occurrence

## Context / 背景
REQ-ACHEM-130 adds a non-compartmental pharmacokinetic (PK) analysis
module that computes `auc_last` (linear trapezoidal rule via
`numpy.trapezoid`), `cmax`, `tmax`, and the terminal elimination rate
constant `k_el` (negative of the slope of `ln(concentrations)` vs. time
over the terminal phase, via ordinary least squares) and the derived
`half_life = ln(2) / k_el`. Two ambiguous situations need an explicit,
documented rule rather than being left to whatever an unreviewed
implementation happens to do: (1) the regression slope for `k_el` can
come out zero or positive (i.e., concentration is flat or rising over
the nominal terminal window — not actually eliminating), which makes
`half_life`/`auc_inf`/`clearance`/`volume_of_distribution` all undefined
(division by zero, or a negative "half life"); (2) more than one time
point can share the same maximum observed concentration, leaving `tmax`
ambiguous. REQ-ACHEM-130's own Acceptance text already specifies that
the first case is "rejected with `ValueError` naming
`concentrations`/`n_terminal` and the constraint 'terminal
concentrations must yield a positive elimination rate constant'", so
this ADR documents and names that already-specified mechanism precisely.

## Decision / 決定
`k_el` must be strictly positive; a fitted terminal slope that is zero
or positive (non-decreasing apparent concentration over the terminal
window) is detected inside `run_pharmacokinetics` immediately after the
terminal-phase OLS fit and raised as `ValueError` naming
`concentrations`/`n_terminal` with the exact constraint string "terminal
concentrations must yield a positive elimination rate constant" —
matching REQ-ACHEM-130's Acceptance verbatim — before `half_life`,
`auc_inf`, `clearance`, or `volume_of_distribution` is ever computed, so
a rejected call never returns a partial result containing a defined
`cmax`/`tmax`/`auc_last` alongside an undefined downstream field. `tmax`
ties are broken by first occurrence: when multiple time points share the
maximum observed concentration, `tmax` is the earliest (smallest-index)
such time point, matching `numpy.argmax`'s own first-occurrence
tie-break behavior, so the implementation can call `argmax` directly
with no separate custom tie-break step.

## Rejected alternatives / 却下した代替案
**Return `half_life = inf` or `half_life = None` for a non-positive
`k_el` instead of raising**: rejected — REQ-ACHEM-130's Acceptance
explicitly specifies a raised `ValueError` with an exact constraint
string for this case; a partial result with an undefined field would
also contradict that already-approved text and require every caller to
separately check for that field's validity.
**Report this failure via DES-ACHEM-002's `{ok: false, parameter,
constraint}` dict shape instead of a raised `ValueError`**: rejected —
REQ-ACHEM-130's own Acceptance text says "rejected with `ValueError`"
for this specific post-fit case, mirroring ADR-0117's identical
deliberate deviation for REQ-ACHEM-120/140's post-fit checks; pre-fit
input validation (point count, strictly increasing `times`, positivity,
`dose`, `n_terminal` range) still uses the standard dict shape via
DES-ACHEM-002, unchanged.
**Break `tmax` ties by latest occurrence, or by reporting all tied time
points as a list**: rejected — latest-occurrence has no
pharmacokinetic rationale and would diverge from `numpy.argmax`'s
default behavior for no benefit; reporting a list would change `tmax`'s
documented scalar type and complicate every caller that expects a
single number.

## Consequences / 結果
`run_pharmacokinetics` performs the `k_el` sign check immediately after
the terminal-phase OLS regression and raises before computing
`half_life`/`auc_inf`/`clearance`/`volume_of_distribution`, so a
rejected run never produces a partial result. Its handler wrapper
(DES-ACHEM-001) must catch this raised `ValueError` and translate it
into the standard dispatch-level rejection outcome, exactly as
ADR-0117 requires for REQ-ACHEM-120/140. The `tmax` tie-break rule
needs no special-cased code beyond calling `numpy.argmax` on the
concentration array, since that is already its default behavior.
