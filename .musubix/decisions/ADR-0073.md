# ADR-0073: Dispatch ai-scientist phases through a manifest-verified orchestrator

## Context / 背景
`DES-AISCI-001` (`REQ-AISCI-001`, `CHANGE-001`, GitHub issue #62 remediation)
must give `ai-scientist` a single skill entry point that can answer in the
caller's language, honor the persisted active phase, and still keep every
phase's domain logic outside the top-level skill wrapper. The concrete
design question is whether routing, phase parsing, gate enforcement, and
handler selection should live in one orchestration component or be spread
across individual phase modules and the manifest.

## Decision / 決定
`ai_scientist.orchestrator.dispatch(instruction, project_name,
requested_phase=None, override_reason=None, ...)` is the authoritative
entry point. It calls `detect_language(instruction)`, resolves the stable
`ResearchProjectHandle`, loads and verifies the phase manifest, determines
the target phase from the explicit argument, `_requested_phase_from_instruction`,
or `active_phase(handle)`, and calls `check_gate(...)` before dispatch whenever
the requested phase differs from the active phase. User-facing status text is
assembled centrally by `_message(...)`, so every phase response stays in the
same language as the incoming instruction.

Actual phase execution is manifest-driven, not hardwired into `dispatch`.
`_dispatch_phase(...)` imports the `modulePath`/`functionName` declared in
the manifest and uses `inspect.signature(...)` to pass only the supported
call arguments (`handle`, `instruction`, `invoker`, `mcp_client`, `gateway`,
`server_name`). That keeps phase handlers as the only owners of phase-specific
behavior while still letting the entry orchestrator enforce the shared gate,
language, and packaging contract from `design.md`.

## Rejected alternatives / 却下した代替案
- **Hard-coding a phase-to-handler switch directly in `dispatch`**: rejected —
  it would duplicate the handler registry that `DES-AISCI-015` already makes
  machine-readable, weaken startup verification, and force orchestration code
  edits for every handler relocation or dependency pin change.
- **Dispatching manifest entries directly to sibling skills instead of importable `src/ai_scientist` functions**: rejected — `DES-AISCI-001` explicitly requires every phase to execute through one importable module function, because some phases (`data-analysis`) delegate to in-repo Python APIs rather than installed skills and others need local evidence bookkeeping around the skill call.
- **Letting each phase handler perform its own gate check and language handling**: rejected — that would duplicate the same active-phase and response-language policy across eight modules, making it easy for one phase to bypass `check_gate(...)` or to answer in a different language than the entry skill saw.

## Consequences / 結果
Future phase additions or routing changes must update the manifest and keep
the handler callable through `dispatch`; phase modules cannot bypass the
orchestrator for normal entry. Covered by the acceptance tests in
`tests/test_ai_scientist_skill_packaging.py`.
