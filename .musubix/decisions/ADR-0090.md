# ADR-0090: Render LaTeX only as deterministic post-processing of the delegated Markdown manuscript

## Context / 背景
`DES-AISCI-018` (`REQ-AISCI-021`, `REQ-AISCI-022`, `CHANGE-001`) must
support either Markdown or LaTeX final manuscripts even though the upstream
`tech-writer` skill produces Markdown only. The design trade-off is whether
format choice should alter how manuscript content is authored, or whether it
should remain a post-processing concern layered on top of one canonical
Markdown draft.

## Decision / 決定
`write_manuscript(...)` always obtains and writes the delegated Markdown
draft first, then reads `manuscriptFormat` from project configuration. If
the format is missing or `markdown`, the Markdown artifact remains the final
manuscript unchanged. If the format is `latex`, ai-scientist writes
`manuscript.tex` by calling `render_latex(markdown_path)` and records the
final artifact as kind `latex`, while still keeping `sourceMarkdownPath` in
metadata so the provenance back to tech-writer's output stays explicit.

`render_latex(...)` is intentionally simple and deterministic: it walks the
Markdown lines in order, maps `# ` to `\section{...}`, `## ` to
`\subsection{...}`, escapes LaTeX-reserved characters through
`_escape_latex(...)`, and wraps the result in a minimal `article` document.
Section headings and body text are emitted in their original order with no
section dropped or moved.

**Known limitation**: the renderer calls `.strip()` on each input line and
on the assembled body, which normalizes (removes) leading/trailing
whitespace, can collapse intentional indentation or trailing-space
formatting within a line, and discards leading/trailing blank lines around
the document boundary. This does not drop or reorder *section content*
(heading and paragraph text, and their relative order, are preserved), but
it is a narrower guarantee than a literal "no content altered" reading of
`DES-AISCI-018`. This whitespace-normalization gap is tracked for dedicated
follow-up as jupytermind#68 rather than fixed here, since changing the
stripping behavior is implementation work outside the scope of this ADR's
debt remediation.

## Rejected alternatives / 却下した代替案
- **Asking `tech-writer` itself to emit LaTeX when LaTeX is configured**: rejected — the sibling skill contract is Markdown-only, and tying authoring format to delegation would break the clean boundary between manuscript generation and rendering.
- **Generating LaTeX directly from upstream evidence artifacts instead of from the completed Markdown manuscript**: rejected — that would create two independent manuscript-assembly paths whose section ordering and content could diverge.
- **Running the LaTeX renderer unconditionally and storing both Markdown and LaTeX as equivalent finals**: rejected — `DES-AISCI-018` says Markdown is the default final artifact unless LaTeX is configured, so unconditional dual-output would change the format contract and add avoidable work.

## Consequences / 結果
Future format support must preserve Markdown as the canonical authored draft
and keep any alternate renderer order-preserving relative to that draft.
Covered by the acceptance tests in `tests/test_ai_scientist_delegation.py`.
