# ADR-0033: Reuse the chemistry-skill static-manifest dispatcher for genomics

## Context / 背景
REQ-AGENOM-001/002 need a bilingual, single-dispatch request router for the new `ai-genomics-scientist` skill. `ai-chemistry-scientist` already has an accepted, reviewed static-manifest dispatcher (NFKC-normalized substring matching over a checked-in JSON manifest, single-match dispatch, clarification on ambiguity, rejection on no match) that this skill's requirements are modeled on verbatim.

## Decision / 決定
Reuse the chemistry skill's dispatcher architecture unmodified except for the genomics-specific manifest file path and the 5 genomics method keys (`sequence-features`, `variant-effect-annotation`, `splice-site-strength`, `gene-set-enrichment`, `pairwise-sequence-alignment`). DES-AGENOM-010 is the one exception that uses per-item validation instead of atomic whole-run validation, handled entirely inside its own handler wrapper rather than by changing the shared dispatcher contract.

## Rejected alternatives / 却下した代替案
Designing a new, genomics-specific dispatch mechanism (for example a trie-based matcher or a different ambiguity policy): rejected because it would introduce an unreviewed architecture with no new requirement driving the change, duplicating logic already accepted and tested in `ai-chemistry-scientist`.
Allowing multiple modules to run per request: rejected because REQ-AGENOM-001 requires at most one module invocation per request, exactly mirroring the chemistry skill's single-dispatch constraint.

## Consequences / 結果
Any future change to the shared dispatch contract (e.g. the ambiguity-resolution policy) should be made once in the shared pattern description and propagated to all skills that reuse it, rather than diverging per skill.
