# ADR-0011: Self-contained data-definition manifest as a new value-object module

## Context / 背景
REQ-AIDS-052 requires tracking, per data field, whether its value is
verified, inferred, reported, or unknown, with derived queries for
unresolved and inferred fields, so that an analysis cannot silently treat
an assumption as a fact.

## Decision / 決定
DES-AIDS-040 introduces a new, self-contained `data_definition` module
with a frozen `FieldValue` value object and a `DataDefinitionManifest`
dataclass. `unresolved_fields()`/`inferred_fields()` are derived by
scanning stored `FieldValue` entries rather than being caller-maintained
flags, so a field's classification cannot drift from its actual stored
status.

## Rejected alternatives / 却下した代替案
- Adding confidence/status fields directly onto existing data-ingestion or
  EDA structures: rejected because it would couple an orthogonal
  provenance concern to modules with their own independent responsibilities
  and no shared architectural boundary.
- Caller-set "unresolved"/"inferred" flags instead of derived queries:
  rejected because a caller-set flag can go stale relative to the
  `FieldValue`'s real status, defeating the purpose of a structurally
  enforceable distinction.

## Consequences / 結果
`data_definition` has no dependency on any other ai-data-scientist module
and introduces no cross-cutting architectural impact; it is a pure,
isolated value-object/manifest module.
