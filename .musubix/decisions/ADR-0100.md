# ADR-0100: Make OOF probabilities conditional on `predict_proba` availability instead of a mandatory result field (DES-AIDS-063)

## Context / 背景
`DES-AIDS-063` (REQ-AIDS-074, REQ-AIDS-075) requires `train_model` to
report fold scores and out-of-fold predictions/probabilities in a
backward-compatible `ModelResult`, while also supporting probability-based
scoring (`roc_auc`, `log_loss`). Not every resolved estimator — built-in or
external (`DES-AIDS-066`) — implements `predict_proba` (e.g.
`LinearRegression` never does; an external classifier-like object might
not either). An earlier draft of this requirement demanded OOF
probabilities unconditionally for every classification run, which a native
`rubber-duck` review (recorded in CHANGE-009.md's Implementation Plan)
flagged as a contract conflict with estimators lacking that capability.

## Decision / 決定
Populate `ModelResult.oof_probabilities` only when cross-validation is
active (`cv_splits`/`cv_strategy` supplied) and the resolved estimator
exposes `predict_proba`, detected per-fold via `_predict_probabilities`
(`hasattr(model, "predict_proba")`, returning `None` otherwise) and only
attempted at all when `model_type == "classification"`. The single-holdout
path (no cross-validation requested) also calls `_predict_probabilities`
internally, but only to feed `compute_score`/`_classification_metrics` for
probability-dependent scoring — the resulting `ModelResult` never sets
`oof_probabilities` on that path (it stays the dataclass default, `None`),
since "out-of-fold" has no meaning without folds; computing and exposing a
holdout-equivalent probability artifact was out of this requirement's
scope. `compute_score` enforces the probability requirement at the scoring
boundary instead: `roc_auc`/`log_loss` call `_require_probabilities`, which
raises `ValueError` naming the scoring metric when `probabilities is None`,
rather than `train_model` silently falling back to a different score. This
keeps "no probability support" and "probability-dependent score requested
without it" as two distinct, explicit failure/non-failure paths: a
classification run with a non-probability estimator and
`scoring="accuracy"` succeeds with `oof_probabilities=None`; the same
estimator with `scoring="roc_auc"` raises as soon as `compute_score`
evaluates the first holdout/fold result, with or without cross-validation
(not before any model is fit).

## Rejected alternatives / 却下した代替案
- Requiring every classification estimator to implement `predict_proba`
  (rejecting non-probability estimators at `resolve_estimator` time):
  rejected because `DES-AIDS-066`'s pluggable-estimator contract only
  requires `fit`/`predict` for general use; many valid classifiers (and all
  regressors) do not implement `predict_proba`, and REQ-AIDS-075's
  acceptance criteria do not require probability support for every run,
  only when probability-dependent scoring or OOF probabilities are
  actually requested/available.
- Silently substituting a non-probability score (e.g. falling back to
  `accuracy`) when `roc_auc`/`log_loss` is requested but unavailable:
  rejected because it would return a result under a different scoring
  metric than the caller asked for, without any signal that the fallback
  occurred — a caller comparing `fold_scores` across runs could silently
  compare incompatible metrics.

## Consequences / 結果
`oof_probabilities` is `None` for any regression run and for any
classification run whose resolved estimator lacks `predict_proba`; callers
must check for `None` rather than assuming it is always populated for
classification. Any future probability-dependent feature added to this
module (a new scoring metric, a new OOF artifact) should follow this same
pattern — detect the capability per-fold and fail fast at the point the
capability is actually required, rather than at estimator-resolution time.
