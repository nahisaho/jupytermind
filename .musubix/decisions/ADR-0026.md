# ADR-0026: Per-module validation granularity (atomic vs. per-batch-item) instead of one universal rule

## Context / 背景
An initial single-pass draft of REQ-ACHEM-003 declared one universal
"reject the whole run" validation rule. Rubber-duck review found this
directly contradicted REQ-ACHEM-010's own acceptance criterion, which
requires a multi-SMILES descriptor batch containing one malformed SMILES
to still return descriptors for every other, valid SMILES in the same
batch (partial success), not a whole-run rejection.

## Decision / 決定
DES-ACHEM-002 defines two validation entry points instead of one:
`validate_parameters(module_name, params)` for atomic, whole-run
validation (used by REQ-ACHEM-020/030/040/050's single-ligand/model/query
modules, and, after the second increment, also by the atomic-validation
modules REQ-ACHEM-060/070/080/090), and `validate_batch_item(module_name,
item_params)` for per-item validation (used once per SMILES by
REQ-ACHEM-010's batch descriptor module, the sole per-item-validated
module in this skill per ADR-0026 — unchanged by the second increment).
matches its own requirement; REQ-ACHEM-003 documents both granularities
explicitly by module rather than asserting one universal rule.

## Rejected alternatives / 却下した代替案
- Forcing REQ-ACHEM-010 to validate atomically (reject the whole batch on
  any invalid SMILES): rejected because this would mean one bad SMILES in
  a 100-molecule batch destroys all 99 valid results, which is a strictly
  worse user experience with no corresponding requirement benefit, and was
  not what REQ-ACHEM-010's acceptance criterion specifies.
- Making every module batch-capable with per-item validation: rejected
  because REQ-ACHEM-020/030/040/050 each operate on exactly one ligand/
  model-fit/query, with no batch concept in their own requirements; adding
  one would be unrequested scope.

## Consequences / 結果
Module implementers must know which granularity their own requirement
calls for and call the matching `DES-ACHEM-002` entry point; this is
explicit in each module's own design section (DES-ACHEM-010 through 050,
and DES-ACHEM-060/070/080/090 added by the second increment, all atomic)
and in REQ-ACHEM-003's Constraints, so it is not an undocumented trap.
