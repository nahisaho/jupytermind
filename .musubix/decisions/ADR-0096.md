# ADR-0096: Pivot grouped bar/barh charts with a collision-free missing-hue sentinel instead of dropping or silently merging missing values (DES-AIDS-074)

## Context / 背景
`DES-AIDS-074` (REQ-AIDS-086) requires `hue`-driven series splitting for
`scatter`/`line`/`hist` (one matplotlib series per `df.groupby(hue,
sort=False)` group, labeled with `str(group_value)`) and, separately, a
reshape-to-pivot path for `bar`/`barh` so each hue level becomes a distinct
plotted series. Pandas' `DataFrame.pivot` drops rows whose pivoted
`columns` key is `NaN` by default, which would silently discard an entire
visible legend series (missing-hue rows) rather than rendering it as the
required `"NaN"` legend entry. The pivot step also needs to reject
duplicate `(x, hue)` rows instead of silently keeping only the first row,
per this design's own stated constraint.

## Decision / 決定
Before pivoting, replace missing (`NaN`) values in the `hue` column with a
randomly generated sentinel string (`secrets.token_hex(8)`-based, checked
against the column's existing non-null string values and regenerated on
collision) via `_normalize_hue_for_pivot`, so `DataFrame.pivot` retains
those rows as an ordinary (non-null) pivot column instead of dropping them.
Detect duplicate `(x, hue)` pairs explicitly with
`DataFrame.duplicated(subset=[x, "__hue__"], keep=False)` immediately before
pivoting and raise `ValueError` if any are found, rather than letting
`pivot` raise its own (less specific) duplicate-index error or silently
keep only one row. After pivoting, rename the sentinel-named column back to
the literal string `"NaN"` so the rendered legend shows that value, and
reorder pivoted columns to the hue column's first-seen order via
`dict.fromkeys` so legend ordering matches `scatter`/`line`/`hist`'s
`groupby(..., sort=False)` ordering. `_pivot_error_values` (for
`DES-AIDS-075`'s grouped error ranges) reuses this same sentinel/duplicate
logic so the `"NaN"` series and its error bars stay aligned through the
same reshape.

## Rejected alternatives / 却下した代替案
- Calling `df[hue].fillna("NaN")` directly before pivoting: rejected
  because a real data value equal to the literal string `"NaN"` would then
  collide with rows that actually have a missing hue, silently merging two
  distinct legend series into one pivot column; the random collision-checked
  sentinel guarantees this cannot happen.
- Relying on `pandas.DataFrame.pivot_table` with an aggregation function
  instead of `pivot` plus an explicit duplicate check: rejected because
  `pivot_table` would silently aggregate (e.g. average) duplicate `(x,
  hue)` rows rather than surfacing them as the explicit `ValueError` this
  design requires, hiding a caller data-quality problem instead of
  reporting it.

## Consequences / 結果
Grouped `bar`/`barh` rendering never silently drops or merges missing-hue
rows, and never silently discards duplicate `(x, hue)` rows; callers must
pre-aggregate duplicates themselves or receive a `ValueError` naming the
offending `(x, hue)` columns. Any future grouped-reshape path added to this
module (e.g. a further grouped chart kind) should reuse
`_normalize_hue_for_pivot`/the same duplicate-detection pattern rather than
re-implementing ad hoc `NaN` handling, to keep missing-value and duplicate
semantics consistent across the module.
