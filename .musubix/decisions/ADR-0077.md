# ADR-0077: Delegate data analysis through ai-data-scientist's real handle and execution path

## Context / 背景
`DES-AISCI-005` (`REQ-AISCI-008`, `CHANGE-001`) defines the only phase that
crosses directly into another in-repo feature's implementation. The problem
is how ai-scientist can reuse ai-data-scientist's notebook and MCP
execution behavior without creating a parallel `ProjectHandle`, drifting
paths, or a second analysis engine.

## Decision / 決定
`delegate_data_analysis(handle, instruction, mcp_client)` requires an MCP
client, resolves ai-data-scientist's real `ProjectHandle` by calling
`ai_data_scientist.project_manager.resolve_project(handle.name)`, verifies
that the returned `root` and `notebook_path` exactly match the
`ResearchProjectHandle`, and then passes that upstream handle to
`ai_data_scientist.project_manager.ensure_notebook(...)` and
`ai_data_scientist.mcp_gateway.run_and_record(...)`. Only after execution
succeeds does ai-scientist record evidence for phase `data-analysis`, with
metadata noting `executionRoutedVia: ai_data_scientist.mcp_gateway`.

This makes ai-data-scientist the owner of notebook creation and execution
semantics while ai-scientist owns phase attribution and evidence capture.
The boundary is therefore a direct Python API reuse, not a reimplemented
skill invocation or a reconstructed handle object.

## Rejected alternatives / 却下した代替案
- **Synthesizing an ai-data-scientist-style handle from `ResearchProjectHandle` fields without calling `resolve_project(...)`**: rejected — it would bypass the upstream feature's own validation and normalization logic, defeating the explicit contract that the real ai-data-scientist resolver is the authority.
- **Invoking ai-data-scientist as an installed sibling skill through the skill registry**: rejected — the design intentionally treats ai-data-scientist as an in-repo Python package sharing the same versioned source tree, so registry pinning is the wrong dependency mechanism for this boundary.
- **Recording notebook evidence before `run_and_record(...)` executes**: rejected — a created notebook path without successful MCP-routed execution would falsely imply that the data-analysis phase actually ran, which is exactly the evidence-quality problem the phase registry is meant to prevent.

## Consequences / 結果
Future data-analysis changes must preserve the real ai-data-scientist API
boundary and the handle-equality assertion before execution proceeds.
Covered by the acceptance tests in `tests/test_ai_scientist_delegation.py`.
