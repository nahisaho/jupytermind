# ADR-0081: Build presentation planning from the recorded manuscript plus cumulative evidence manifest

## Context / 背景
`DES-AISCI-009` (`REQ-AISCI-014`, `CHANGE-001`) must turn completed
research work into a presentation plan without making ai-scientist itself
responsible for slide-storytelling logic. The key design decision is what
concrete inputs should be sent to `presentation-planner` so it sees both the
final narrative artifact and the broader project evidence context.

## Decision / 決定
`build_presentation(handle, invoker)` requires a previously recorded
`manuscript-writing` artifact via `latest_evidence(...)`; if none exists, it
fails immediately. When present, it queries all evidence for the project,
excludes only existing `presentation` records, and passes two things to the
pinned `presentation-planner@0.3.0` dependency in `plan` mode: the
manuscript artifact path and an `evidenceManifest` list containing each
prior record's `phase`, `artifactPath`, `artifactKind`, `createdAt`, and
`metadata`. The returned plan is written to `presentation-plan.md` and
recorded as `presentation` evidence.

This keeps presentation generation delegated while ensuring the planner is
grounded in the manuscript and the supporting research artifacts, not in a
bare prompt alone. The phase therefore consumes the same durable evidence
model used elsewhere instead of inventing a presentation-specific context
channel.

## Rejected alternatives / 却下した代替案
- **Passing only the manuscript path and omitting the evidence manifest**: rejected — the planner would lose the structured provenance and supporting artifacts that the design explicitly says should accompany the final manuscript.
- **Delegating directly from notebook/data-analysis artifacts without requiring a manuscript**: rejected — `DES-AISCI-009` treats the manuscript as the project's narrative synthesis, so bypassing it would allow presentation planning before the main written argument exists.
- **Implementing slide-outline generation locally in ai-scientist instead of calling `presentation-planner`**: rejected — it would duplicate a dedicated sibling skill and move presentation-structuring responsibility into the wrong component.

## Consequences / 結果
Future presentation behavior must continue to require a manuscript artifact
and to record presentation output as its own evidence phase. Covered by the
acceptance tests in `tests/test_ai_scientist_delegation.py`.
