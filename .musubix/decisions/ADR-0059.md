# ADR-0059: Use scikit-learn's StandardScaler directly for the leakage-safe fit/transform API

## Context / 背景
`DES-AIDS-061` (REQ-AIDS-073, new) needed a leakage-safe
`fit_features`/`transform_features` pair so a model-selection/
cross-validation caller can fit scaling statistics on a training fold and
apply them to a disjoint fold without ever deriving statistics from the
held-out rows (GitHub #51). The existing single-call `scale` operation in
`engineer_features` already delegated to scikit-learn's `StandardScaler`.

## Decision / 決定
Keep `StandardScaler` as the sole statistics-estimating primitive behind
`fit_features`/`transform_features`: `fit_features` returns a frozen
`FittedFeatureState` wrapping exactly the `StandardScaler` instance
produced by `StandardScaler().fit(df[columns])`, and `transform_features`
calls only `fitted_state.scaler.transform(...)`, never re-fitting. This
reuses scikit-learn's own well-tested, well-documented
fit/transform-separation contract (the same contract every other
scikit-learn estimator follows) instead of reimplementing mean/variance
bookkeeping, so `FittedFeatureState` is a thin, auditable wrapper rather
than a new statistics engine.

## Rejected alternatives / 却下した代替案
- **Hand-rolled mean/variance tracking** (storing raw `mean_`/`scale_`
  arrays instead of the `StandardScaler` object itself): rejected because
  it would duplicate logic scikit-learn already implements and tests,
  including its documented zero-variance convention (`scale_=1`), for no
  behavioral benefit, while adding a surface where a reimplementation bug
  could silently diverge from `StandardScaler`'s reference semantics.
- **A fully custom leakage-safe engine covering all operations (including
  `aggregate`) in one new abstraction**: rejected as out of scope for
  REQ-AIDS-073, which only targets the `scale` leakage risk originally
  reported in #51; generalizing the fit/transform split to
  `aggregate`/other statistics-estimating operations is deferred to a
  future change (documented in CHANGE-008's Scope as a residual risk).
- **Always re-fitting inside `transform_features` when given a new
  `df`**: rejected because it would silently reintroduce the exact
  leakage risk this change exists to close — the whole point of
  `FittedFeatureState` is that `transform_features` never calls `fit`/
  `fit_transform` or otherwise recomputes statistics from its `df`
  argument; it only applies the already-fitted `scaler`.

## Consequences / 結果
Any future statistics-estimating operation added to the leakage-safe API
should follow the same pattern: wrap the corresponding scikit-learn
estimator directly in a frozen `FittedFeatureState`-like container rather
than reimplementing its statistics. `transform_features` remains strictly
bound to never touching its `df` argument beyond selecting columns and
calling `.transform(...)`, preserving the leakage-safety guarantee.
Covered by `tests/test_feature_engineering.py` (REQ-AIDS-073 acceptance
tests, including the zero-variance and exact-reproduction-of-legacy-`scale`
cases).
