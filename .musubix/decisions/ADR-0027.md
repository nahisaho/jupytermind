# ADR-0027: Plain-dict JSON-safe evidence record with no ndarray codec

## Context / 背景
REQ-ACHEM-004 requires every module run to be recorded with exactly three
top-level keys (`metadata`, `parameters`, `result`) and to be
deterministically reproducible. `ai-materials-scientist`'s sibling
evidence design (DES-AIMS-003) needs a `to_json`/`from_json` ndarray codec
because its simulation modules return `numpy.ndarray` field snapshots.
None of `ai-chemistry-scientist`'s 5 modules return ndarrays: every
result is already composed of scalars, strings, and lists/dicts of these
(descriptor values, boolean flags, violation-name lists, regression
coefficients, ranked similarity lists, a docking score).

## Decision / 決定
DES-ACHEM-003's `record_run` returns a plain JSON-safe `dict` directly —
no `arrays` key, no `to_json`/`from_json` ndarray encode/decode step. The
`metadata` key always includes `module`, `schema_version`, and
`rdkit_version`; it additionally includes `scikit_learn_version` only for
the QSAR module (REQ-ACHEM-030), which is the only module depending on
scikit-learn. No `seed` field is recorded (unlike DES-AIMS-003), because
REQ-ACHEM-004 explicitly states every module is deterministic with no
stochastic step.

## Rejected alternatives / 却下した代替案
- Copying DES-AIMS-003's `arrays`-based RunRecord shape verbatim (with an
  always-empty `arrays` dict): rejected as needless structural complexity
  carried over from a sibling module with a genuinely different output
  shape; REQ-ACHEM-004 itself specifies `result`, not `arrays`, as the
  third top-level key.
- Recording a `seed` field set to `None` for uniformity with
  `ai-materials-scientist`: rejected because REQ-ACHEM-004's Constraints
  state plainly there is no seed to record for any of the 5 modules;
  adding a field that is always `None` would misleadingly suggest some
  module might one day be stochastic.

## Consequences / 結果
If a future chemistry module genuinely needs to report array-shaped data
(e.g., a dense similarity matrix), that module's own requirement and
design section must define its own JSON-safe array representation (e.g.,
nested lists); DES-ACHEM-003 does not pre-provide an ndarray codec.
