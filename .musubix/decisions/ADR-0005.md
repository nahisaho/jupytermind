# ADR-0005: Strict kebab-case slug policy for project identifiers

## Context / 背景
REQ-AIDS-002/028 require project-scoped notebook paths derived from a
user-supplied project name, and a rubber-duck review flagged that an
unvalidated name risks path traversal or invalid filesystem paths.

## Decision / 決定
Accept only project names matching a strict slug pattern
(`^[a-z0-9]+(-[a-z0-9]+)*$`, ASCII lowercase letters, digits, and single
hyphens, no leading/trailing/double hyphens). Any other input — including
path separators, `..`, absolute paths, or non-ASCII characters — is rejected
by the Project & Notebook Manager before any filesystem call, with a
localized error explaining the allowed pattern.

## Rejected alternatives / 却下した代替案
- Sanitizing arbitrary names (stripping disallowed characters): rejected
  because silent transformation can cause two different user-intended names
  to collide on the same notebook path, and does not give the user a clear
  mental model of what is allowed.
- Allowing Unicode/Japanese project names directly in the path: rejected for
  MVP to avoid filesystem/encoding edge cases across the Windows/macOS/Linux
  matrix; a future ADR may add a separate display-name field mapped to a slug.

## Consequences / 結果
The skill must ask the user to choose or confirm an ASCII slug identifier
when a natural-language project name is not already slug-shaped; this is a
UX requirement carried into implementation, tested directly by REQ-AIDS-028's
acceptance criterion.
