# ADR-0091: Enforce completion through a configured test-suite gate that rejects skips as well as failures

## Context / 背景
`DES-AISCI-019` (`REQ-AISCI-024`, `CHANGE-001`) is the final implementation
readiness gate for ai-scientist. The design issue is what concrete policy
should turn an arbitrary configured test command into a binary gate that
matches the requirement's promise: zero failures and zero unapproved skipped
tests, including the integration boundary with ai-data-scientist.

## Decision / 決定
`run_configured_test_suite(command: Sequence[str])` executes the supplied
command with `subprocess.run(..., check=False, capture_output=True, text=True)`
and treats the completed process itself as the gate evidence. A non-zero
exit code raises `TestSuiteGateError("Configured test suite failed.")`.

Originally, even when the process exited zero, ai-scientist concatenated
stdout and stderr and applied `_SKIPPED_TEST_RE` to reject outputs
reporting skipped tests, raising
`TestSuiteGateError("Configured test suite reported skipped tests.")` for
any skip, approved or not. This path remains as the fallback for commands
that do not invoke pytest; see Resolved, below, for the pytest-specific
structural path that superseded it for pytest invocations.

This deliberately keeps the gate tool-agnostic while still encoding the
repository's stronger policy that skipped tests are not equivalent to a
passing run for the common pytest-style `"N skipped"` summary-line case.

**Resolved** (originally a known limitation, closed by CHANGE-019 per
jupytermind#67): `run_configured_test_suite(...)` now accepts an
`approved_skips: frozenset[str] = frozenset()` parameter. For any command
that invokes `pytest`, it transparently appends `--json-report
--json-report-file=<tmp>`, then — after the existing non-zero-exit check —
parses the JSON report structurally for `outcome == "skipped"` test
nodeids via `_unapproved_skips(...)`. Only a skipped nodeid absent from
`approved_skips` raises `TestSuiteGateError`, so the gate no longer depends
on console wording and can tolerate an explicitly approved skip. Commands
that do not invoke pytest still fall back to the original `_SKIPPED_TEST_RE`
text check unchanged. Covered by `TEST-AISCI-044` and `TEST-AISCI-045`.

## Rejected alternatives / 却下した代替案
- **Accepting any zero-exit test run even if the output reports skipped tests**: rejected — that would directly contradict `REQ-AISCI-024`'s zero-unapproved-skips policy and would let incomplete coverage masquerade as readiness.
- **Building the gate around pytest-specific JSON or JUnit parsing only**: rejected — the interface is intentionally `command: Sequence[str]`, so the gate should work for the configured suite generically instead of binding ai-scientist to one runner's report schema.
- **Proving readiness from linked test files alone without executing the configured suite**: rejected — static linkage can show intended coverage, but it cannot prove that the tests currently pass or that integration boundaries still work.

## Consequences / 結果
Future quality gates must treat only an *unapproved* detected pytest-report
skip as release-blocking; an entry explicitly listed in `approved_skips`
no longer fails the gate (see Resolved above). Non-pytest commands keep the
original unconditional text-regex skip check, since no structural report
format is assumed for them. The repository's linked tests remain the
substantive proof behind the gate. Covered by the acceptance tests in
`tests/test_ai_scientist_skill_packaging.py` and
`tests/test_ai_scientist_tdd_gate.py`.
