# ADR-0009: Read-only nbformat consumption for notebook audit (no new storage format)

## Context / 背景
REQ-AIDS-045 requires a notebook audit capability that reports nbformat
validity, unexecuted/error cells, chart cells, and evidence-manifest
staleness, without risking corruption of the notebook under audit.

## Decision / 決定
DES-AIDS-033 loads the notebook via `nbformat` and never calls
`nbformat.write` or otherwise mutates the file on disk. It reuses the exact
evidence cross-check semantics already defined by DES-AIDS-010 (the
`\`\`\`evidence` fenced JSON manifest) rather than introducing a second,
divergent notebook evidence format.

## Rejected alternatives / 却下した代替案
- A dedicated audit-only serialization format or cache: rejected because it
  would duplicate DES-AIDS-010's existing evidence manifest schema and
  introduce a second source of truth to keep in sync.
- Writing audit findings back into the notebook file: rejected because the
  requirement is explicitly read-only; writing back would risk corrupting
  a notebook that may be open in a live Jupyter/MCP session.

## Consequences / 結果
The audit module has a hard dependency on DES-AIDS-010's manifest matching
rule staying stable; any future change to that rule must be reflected here
as well. No new file format or migration path is introduced.
