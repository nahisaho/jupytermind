# ADR-0086: Represent MCP unavailability as a pure typed classifier carrying server and phase

## Context / 背景
`DES-AISCI-014` (`REQ-AISCI-019`, `CHANGE-001`) exists so failed MCP access
never degrades into silent skipping or ambiguous generic errors. The
concrete design issue is how to communicate an unreachable server in a way
that callers and users can attribute to both the server that failed and the
phase that requested it.

## Decision / 決定
Ai-scientist uses a dedicated exception type,
`MCPUnavailableError(server_name, phase, error)`, and a pure helper,
`classify_mcp_failure(server_name, phase, error) -> MCPUnavailableError`.
The classifier has no side effects and no dependency on gateway or state
modules; it only constructs the explicit error object and message. Both the
generic gateway path and managed-startup path call the same classifier, so
connection failures and startup-time health-check failures surface through
one domain error contract.

This makes server attribution (`server_name`) and workflow attribution
(`phase`) first-class fields on the exception rather than strings buried in
ad hoc logs. Phase handlers can therefore fail cleanly before evidence is
recorded, while still reporting which request path lost tool access.

## Rejected alternatives / 却下した代替案
- **Raising a plain `RuntimeError` with only formatted text**: rejected — callers and tests would lose structured access to `server_name` and `phase`, making downstream reporting and assertions more fragile.
- **Swallowing MCP failures and returning an empty or partial result object**: rejected — that would allow phases to continue as if tool-backed work had succeeded, directly conflicting with the requirement to avoid silent skipping and fabricated evidence.
- **Having the classifier inspect or mutate the evidence/state stores while building the error**: rejected — `DES-AISCI-014` is intentionally dependency-light to avoid cycles with callers and to keep failure construction usable from both the gateway and managed-runtime layers.

## Consequences / 結果
Future MCP failure handling must continue to raise the typed classifier
result before phase completion evidence is written. Covered by the
acceptance tests in `tests/test_ai_scientist_mcp.py`.
