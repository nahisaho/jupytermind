# ADR-0089: Gate phase completion on exact phase-attributed evidence presence

## Context / 背景
`DES-AISCI-017` (`REQ-AISCI-020`, `CHANGE-001`) determines when a phase may
actually become complete in the persisted lifecycle state. The design
question is what proof threshold `mark_phase_complete(...)` should trust:
handler return values and file existence, or durable evidence records whose
phase and project attribution can be checked uniformly.

## Decision / 決定
`validate_completion_evidence(handle, phase) -> bool` is a narrow predicate
over the evidence registry. It queries only records for the requested phase
and returns true only when at least one record matches the exact project
name, the exact phase string, and has a non-empty `created_at` timestamp.
`mark_phase_complete(...)` in `phase_state.py` calls this predicate before
persisting any completion transition and raises `ValueError` if the check
fails.

This intentionally keeps the completion rule metadata-based and phase-exact.
A real artifact produced for another phase, or an unrecorded artifact lying
in the workspace, does not count unless the registry proves it was recorded
for this project and this phase.

## Rejected alternatives / 却下した代替案
- **Treating a successful handler return value as sufficient completion proof**: rejected — handler return payloads are transient process values, not durable evidence that survives the next CLI invocation or can be audited independently.
- **Accepting any artifact found under the phase's directory, regardless of registry attribution**: rejected — directory presence alone does not prove when or why the artifact was created, and it would let stray files satisfy the gate without phase-scoped metadata.
- **Allowing evidence from a neighboring phase to satisfy completion when the artifact seems semantically related**: rejected — the requirement and implementation are intentionally strict that completion is phase-specific, so cross-phase artifacts must not satisfy the check.

## Consequences / 結果
Future completion logic must keep exact phase attribution as the gate and
must not bypass the registry when persisting lifecycle transitions. Covered
by the acceptance tests in `tests/test_ai_scientist_phase_state.py`.
