# ADR-0066: Resolve chart metadata per-image, with cell-level fallback only for a single unambiguous image

## Context / 背景
`DES-AIDS-060` (REQ-AIDS-072) addresses the remainder of GitHub #40:
`audit_visual_outputs` computed one `chart_metadata` value per cell, so a
cell containing multiple chart images could never have its individual
images correctly matched to their own metadata, and officially-rendered
charts were flagged "unaudited" even when `DES-AIDS-059` had started
persisting metadata on the output itself.

## Decision / 決定
Iterate image outputs individually per cell. For each image output,
resolve metadata in strict priority order: (1) the output's own
`metadata["chart"]` when it is a non-empty dict; (2) the cell-level
`metadata["chart"]`, but **only** when the cell has exactly one qualifying
image output and that output's own metadata has no `"chart"` key at all
(distinct from an empty/invalid one — an output that tried and failed to
carry its own chart metadata never silently inherits the cell's); (3)
`None`, which produces the existing "unaudited" finding, now tagged with
`(cell_index, output_index)` instead of a bare cell index.
`VisualAuditFinding` gains an additive, defaulted `output_index: int |
None = None` field so every existing test construction remains valid.

## Rejected alternatives / 却下した代替案
- **Applying the cell-level `chart_metadata` to every image in a
  multi-image cell**: rejected — this is exactly the ambiguity bug being
  fixed; one image's valid metadata must never be attributed to a sibling
  image in the same cell.
- **Falling back to cell-level metadata even when an output's own metadata
  is present but invalid/empty**: rejected per REQ-AIDS-072's explicit
  no-fallback-on-malformed-output-metadata rule — a malformed output-level
  entry is a defect to surface as "unaudited," not a reason to silently
  substitute a different image's context.
- **Making `output_index` a mandatory (non-defaulted) field on
  `VisualAuditFinding`**: rejected — it would break every existing test
  construction/comparison of `VisualAuditFinding(...)` for prior findings
  that never populated this field, forcing an unrelated mass test rewrite
  for a field whose value is genuinely optional for cell-level-only
  findings.

## Consequences / 結果
Any future per-output audit refinement in `audit_visual_outputs` must
preserve this strict per-output-then-single-image-cell-fallback priority
order, since REQ-AIDS-072's acceptance criteria depend on never
cross-attributing metadata between sibling images. Covered by the
REQ-AIDS-072 acceptance tests in `tests/test_notebook_audit.py`.
