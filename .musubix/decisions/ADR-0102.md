# ADR-0102: Merge caller-supplied AutoML candidates into the built-in registry by name, overriding on collision (DES-AIDS-065)

## Context / 背景
`DES-AIDS-065` (REQ-AIDS-077, REQ-AIDS-078) requires `run_automl` to accept
an optional `candidate_estimators` mapping of external estimators/factories
while preserving the existing built-in candidate set when it is omitted, so
legacy AutoML callers keep evaluating the same default model set. Both the
built-in registry (`MODEL_BUILDERS[model_type]`, keyed by model name) and
`candidate_estimators` (keyed by caller-chosen name) are name-keyed
collections, and a candidate must flow through the same shared-fold
training/ranking path (`DES-AIDS-064`) regardless of its origin.

## Decision / 決定
`build_candidate_estimators` starts from `{name: None for name in
MODEL_BUILDERS[model_type]}` (each built-in model name mapped to the
sentinel `None`, meaning "resolve via the built-in registry") and then
`dict.update`s in `candidate_estimators` when supplied, so a caller-supplied
name identical to a built-in name *replaces* that entry with the external
estimator/factory rather than erroring or keeping both. In the candidate
loop, `run_automl` resolves each entry by its sentinel: `estimator is None`
means call `train_model` with `model_name=model_name` (built-in path);
otherwise call it with `estimator=estimator` (external path), where
`resolve_estimator` (`DES-AIDS-066`) ignores `model_name` entirely once
`estimator` is non-`None`. This keeps a single ranked-candidates loop
(`DES-AIDS-065`'s `ranked_candidates`) handling both origins uniformly,
reusing `DES-AIDS-064`'s shared-fold-plan guarantee without any
candidate-origin-specific branching in the ranking/sorting logic itself.

## Rejected alternatives / 却下した代替案
- Keeping built-in and external candidates in two separate lists evaluated
  and ranked independently, then merged after the fact: rejected as
  unnecessary complexity — both candidate kinds already produce identical
  `{model_name, metric, fold_scores, result}` entries once resolved, so a
  single merged dict plus one loop is sufficient and keeps sorting
  (ascending/descending by metric) in one place.
- Raising an error when a caller-supplied name collides with a built-in
  model name, instead of silently overriding: rejected because
  REQ-AIDS-078's acceptance criteria describe `candidate_estimators` as
  letting a caller supply their own estimators without additional naming
  constraints, and name-based override gives a caller a documented way to
  replace a specific built-in candidate's implementation without first
  removing it.

## Consequences / 結果
A caller supplying a `candidate_estimators` name that matches a built-in
model name silently replaces that built-in candidate for this call only
(the global `MODEL_BUILDERS` registry is never mutated); callers relying on
every built-in model name always using its built-in implementation must
avoid reusing those names in `candidate_estimators`. Any future candidate
source added to AutoML (e.g. a third registry) should follow this same
name-keyed-dict-merge pattern to stay consistent with how built-in/external
candidates are already unified.
