# ADR-0098: `chart_metadata_from_figure` reads only the figure's first axes, as a pure, non-mutating introspection helper (DES-AIDS-076)

## Context / 背景
`DES-AIDS-076` (REQ-AIDS-088) requires a way for a caller that hand-draws a
matplotlib `Figure` (outside `render_chart`) to still produce an auditable
`ChartMetadata`/`RenderedChart` so `build_image_output`/`record_chart`'s
existing metadata-persistence path (`DES-AIDS-048`, `DES-AIDS-049`,
`DES-AIDS-059`) can audit it unchanged. `render_chart` itself already
builds `ChartMetadata` internally via its own axes, but no public entry
point previously existed for a figure `render_chart` did not create — and
`heatmap` (`DES-AIDS-073`) adds a `fig.colorbar` call that creates an
auxiliary colorbar axes on the same figure, which must not be mistaken for
the main plotted axes when introspecting title/labels/legend.

## Decision / 決定
Add a public function, `chart_metadata_from_figure(fig, *, missing_glyphs=
())`, that reads `fig.axes[0]` as the single authoritative plotted axes
(raising `ValueError` if the figure has no axes at all) and returns a
`ChartMetadata` built from `ax.get_title()`, `ax.get_xlabel()`,
`ax.get_ylabel()`, and `ax.get_legend()` (with `legend_title` taken from
`legend.get_title().get_text()` when a legend exists, else `None`). The
function only reads existing figure state — it does not mutate the figure,
force a canvas redraw, or call `fig.savefig`; the caller remains
responsible for saving PNG bytes and constructing
`RenderedChart(png_bytes, chart_metadata_from_figure(fig))` itself.
`missing_glyphs` defaults to an empty tuple, documented as a known
limitation: glyph-rendering warnings from matplotlib's font substitution
cannot be reliably recovered from an already-rendered figure after the
fact, so this helper cannot detect them itself the way `render_chart`'s
`warnings.catch_warnings` capture does internally. `render_chart` itself is
refactored to call this same helper internally (passing the warnings it
already captured), so both the internal and external metadata-construction
paths share identical title/label/legend-reading logic.

## Rejected alternatives / 却下した代替案
- Accepting an explicit axes argument (`chart_metadata_from_figure(ax,
  ...)`) instead of a figure, to avoid any ambiguity about which axes is
  read: rejected because the requirement and existing call sites assume a
  `Figure` the caller already has in hand (matching `fig.savefig`'s own
  figure-level API), and `fig.axes[0]` is already deterministic for every
  kind this module produces, including `heatmap`'s colorbar axes (which
  matplotlib always appends after the main axes, not before it).
- Attempting to re-render or inspect saved PNG bytes directly to recover
  glyph warnings instead of leaving `missing_glyphs` caller-supplied:
  rejected as substantially more complex (re-parsing rendered raster output)
  for a capability `render_chart`'s own internal capture already provides
  more reliably at render time.

## Consequences / 結果
Callers that hand-draw a figure with multiple axes (beyond `heatmap`'s own
colorbar case) must ensure their primary plotted axes is `fig.axes[0]`, or
this helper will read the wrong axes; this is a documented constraint, not
a defect. `missing_glyphs` is always empty unless the caller explicitly
passes known codepoints, so hand-drawn figures get strictly weaker
glyph-warning auditing than `render_chart`-produced ones; any future
capability to recover glyph warnings from a figure after the fact would
need a new design decision, not a change to this helper's existing
contract.
