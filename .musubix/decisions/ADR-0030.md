# ADR-0030: Pinned 5-compound fixed-rank training fixture instead of an arbitrary synthetic QSAR dataset

## Context / 背景
An initial REQ-ACHEM-030 draft specified only a count ("5 compounds") and
a synthetic exact-linear activity law, without pinning the actual training
SMILES or query SMILES. Rubber-duck review found this insufficient: 5
samples is enough *in count* for a 3-feature-plus-intercept OLS fit but not
necessarily sufficient *in rank* — a design matrix `[1, MolWt, MolLogP,
TPSA]` can still be rank-deficient (e.g., near-collinear descriptors),
which would make OLS coefficients non-unique even with zero residual, and
the fixture was not reproducible without a pinned compound list.

## Decision / 決定
REQ-ACHEM-030's acceptance fixture pins exactly 5 named training compounds
(aspirin, ibuprofen, caffeine, paracetamol, naproxen) and 1 query compound
(diclofenac, not in the training set), each with an explicit SMILES
string. The activity law `activity = 2.0*MolWt - 50.0` is applied to each
training compound's own RDKit-computed `MolWt` (with `MolLogP`/`TPSA`
coefficients fixed at `0.0`). The resulting augmented design matrix
`[1, MolWt, MolLogP, TPSA]` for these 5 compounds was empirically verified
(via `numpy.linalg.matrix_rank`) to have full column rank 4, so the OLS
fit is guaranteed unique, not merely zero-residual. DES-ACHEM-030
additionally validates this rank condition for *any* user-supplied
training set (not just the fixture), rejecting a rank-deficient training
set under REQ-ACHEM-003 before any `LinearRegression.fit` call.

REQ-ACHEM-003's "before performing any ... model fit" constraint is
interpreted as governing the QSAR-specific OLS fit/prediction computation
only. Computing each training/query molecule's descriptors in order to
check SMILES parseability and the design matrix's rank is part of
DES-ACHEM-002's atomic validation step itself, not the governed
computation that validation is meant to precede. `validate_parameters`'s
boolean-shaped return (`{ok: true}` / `{ok: false, ...}`) carries no
descriptor payload, so `run_qsar_modeling` independently recomputes the
same descriptors for the actual fit/prediction once validation has
passed; since REQ-ACHEM-004 requires every computation to be a
deterministic pure function of its inputs, this intentional duplication
always yields identical values and is an accepted cost, not a
correctness risk.

## Rejected alternatives / 却下した代替案
- Leaving the training/query SMILES unpinned and trusting "any 5
  compounds satisfying the linear law will do": rejected because this
  does not guarantee full rank, and is not a reproducible, single
  deterministic acceptance fixture as this project's TDD conventions
  require.
- Checking only the training-set *count* (`>= 5`) with no rank check:
  rejected because a rank-deficient-but-5-or-more-row training set can
  still yield non-unique coefficients that fail the exact-recovery
  acceptance criterion, which would make REQ-ACHEM-030's test flaky or
  implementation-dependent.

## Consequences / 結果
Any future change to the pinned training/query SMILES list requires
re-verifying the design matrix's full-rank condition and recomputing the
expected coefficients/intercept/predictions; this is a manual step tied to
this ADR and REQ-ACHEM-030's acceptance criterion, not automatically
re-derived.
