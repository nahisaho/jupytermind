# ADR-0085: Treat external MCP servers as connect-only endpoints with no local lifecycle ownership

## Context / 背景
`DES-AISCI-013` (`REQ-AISCI-018`, `CHANGE-001`) covers servers that are
already running outside ai-scientist. The design trade-off is whether the
external connector should share the managed lifecycle machinery for
convenience, or remain a minimal connector whose only job is to turn a
validated external entry into a client.

## Decision / 決定
`connect_external_server(entry: ExternalServerConfig) -> HttpMcpClient`
accepts only an `ExternalServerConfig` instance and returns
`HttpMcpClient(entry.endpoint)`. `HttpMcpClient.call_tool(...)` posts JSON to
`endpoint.rstrip('/') + '/tool'` and converts transport failures into
`ConnectionError`, leaving lifecycle decisions to the external server owner.
No start, stop, or port-substitution logic is performed for this mode.

This keeps the external connector intentionally narrow: ai-scientist either
has a valid external endpoint and talks to it, or it fails fast. The module
therefore does not pretend that external servers are partially managed local
processes.

## Rejected alternatives / 却下した代替案
- **Routing external servers through the managed process manager with a dummy launch command**: rejected — that would fabricate local lifecycle ownership for something ai-scientist neither starts nor stops, and it would blur the real distinction between managed and external modes.
- **Accepting either managed or external config objects and branching silently at runtime**: rejected — `DES-AISCI-013` is specifically about the external path, so the function contract should reject wrong-mode entries instead of making mode mistakes harder to notice.
- **Performing an eager health check inside `connect_external_server(...)` before returning a client**: rejected — configuration loading and connection creation stay separate from availability classification, which is already handled uniformly by the gateway/failure path when a real tool call is attempted.

## Consequences / 結果
Future external-mode work must preserve the no-spawn/no-stop boundary and
keep lifecycle management out of this connector. Covered by the acceptance
tests in `tests/test_ai_scientist_mcp.py`.
