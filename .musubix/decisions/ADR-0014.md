# ADR-0014: Document Jupyter MCP concurrent-write risk instead of adding write coordination

## Context / 背景
REQ-AIDS-059 requires surfacing the risk that a direct `enqueue_write` call
against a notebook file that is simultaneously open in a Jupyter MCP
session can be silently overwritten when that MCP session later saves.

## Decision / 決定
DES-AIDS-047 adds an explicit risk/mitigation note to SKILL.md's
notebook-write workflow step and to `project_manager.enqueue_write`'s
docstring, recommending routing writes through the active MCP session (or
pausing MCP-side saves) instead of calling `enqueue_write` directly while
an MCP session holds the file open. No runtime write-coordination
mechanism (locking, session handshake, etc.) is introduced.

## Rejected alternatives / 却下した代替案
- Adding a file lock or MCP-session handshake before `enqueue_write`:
  rejected for this change because it would be a nontrivial behavior
  change requiring its own TDD cycle, while REQ-AIDS-059's accepted
  acceptance criterion explicitly only requires documenting the risk, not
  changing runtime behavior.

## Consequences / 結果
The concurrent-write race itself remains possible; this decision only
ensures it is documented so operators/agents can avoid triggering it. A
future change introducing real write coordination would need its own
requirement, design, and ADR.
