# ADR-0003: Structured insight evidence manifest embedded in the markdown cell

## Context / 背景
REQ-AIDS-009/010/027 require every reasoning-based insight to carry a
machine-checkable link to the executed cell that justifies it, because a
rubber-duck review found that cell adjacency alone cannot prove an insight is
actually supported by prior output (a hallucinated claim can still sit next
to a real cell). The user separately specified that insight rationale must
live inside the notebook (markdown + code cells), not a side-channel log.

## Decision / 決定
Encode the evidence manifest as a strict single-line JSON object inside the
insight markdown cell's source (e.g. a fenced ```evidence block), containing
the source cell's `execution_count`, the cited output value(s), and a claim
type. The Insight & Evidence Engine (DES-AIDS-010) validates this manifest
against the actual notebook JSON before the cell is written, and refuses to
write the insight (REQ-AIDS-010) if validation fails.

## Rejected alternatives / 却下した代替案
- Separate insight log file (JSON/Markdown outside the notebook): rejected
  per explicit user preference that evidence must stay inside the Notebook
  itself, and because it would require cross-file consistency checks the
  notebook-only approach avoids.
- Adjacency-only evidence (current REQ-AIDS-009 wording without a manifest):
  rejected per rubber-duck review; unenforceable because "the output is
  referenced by the insight text" cannot be verified without a structured,
  machine-parseable citation.

## Consequences / 結果
Every insight-writing code path must run the manifest validator before
appending a cell; this validator becomes a required dependency of
DES-AIDS-010 and a direct test target for REQ-AIDS-027's acceptance
criterion. The manifest format itself becomes a compatibility surface that
must be versioned if changed later.
