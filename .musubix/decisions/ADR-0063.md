# ADR-0063: Validate every evidence-fence block and its supporting_evidence entries, never only the first

## Context / 背景
`DES-AIDS-057` (REQ-AIDS-069) addresses GitHub #44:
`notebook_audit._extract_evidence_manifest` inspected only the first
fenced evidence block in a cell and never validated an optional
`supporting_evidence` list, so a malformed second block or a malformed
supporting-evidence entry produced no audit finding at all.

## Decision / 決定
Replace the single-result extraction with
`_extract_evidence_manifests`, which collects every fenced block's parsed
payload in appearance order via `finditer`, yielding `None` (not silently
skipping) for a block that fails to parse as a JSON object. The audit loop
turns every `None` entry into an error-severity "malformed evidence block"
finding, and validates each well-formed block's optional
`supporting_evidence` list entry-by-entry against an explicit shape
(`int execution_count`, non-empty `str cited_value`), reporting any
shape violation as its own error-severity finding. A cell with zero
fences still produces the existing single "missing evidence manifest"
finding — this per-block validation only activates once at least one
fence is present.

## Rejected alternatives / 却下した代替案
- **Keeping single-block validation and treating extra blocks as
  ignorable**: rejected — this is exactly the bug being fixed; a second,
  malformed block would pass audit silently, undermining the evidence
  requirement's purpose.
- **Validating `supporting_evidence` only for shape, not resolution against
  a real cell**: rejected — an entry with a syntactically valid but
  factually unresolvable `cited_value`/`execution_count` pair is exactly
  the kind of unverifiable claim the evidence-manifest mechanism exists to
  catch, so it is resolved via the same `_find_evidence_cell` check used
  for the primary citation.
- **Silently dropping a malformed block instead of reporting it**:
  rejected because a dropped block is indistinguishable from "no block
  present" to a report reader, which would hide exactly the defect this
  design is meant to surface.

## Consequences / 結果
Any future evidence-fence consumer in `notebook_audit` must enumerate all
fenced blocks in a cell, not just the first, and must treat a malformed
block as a reportable finding rather than silently ignoring it. Covered by
the REQ-AIDS-069 acceptance tests in `tests/test_notebook_audit.py`.
