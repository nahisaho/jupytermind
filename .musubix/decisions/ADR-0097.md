# ADR-0097: Normalize `xerr`/`yerr` through one shared helper accepting a column name or a (lower, upper) pair (DES-AIDS-075)

## Context / 背景
`DES-AIDS-075` (REQ-AIDS-087) requires `scatter`/`line`/`bar`/`barh` to
accept optional `xerr`/`yerr` arguments that can express either a symmetric
error range (one column) or an asymmetric error range (separate lower/upper
columns), feeding `Axes.errorbar` (`scatter`/`line`) or pandas' bar-plotting
`yerr=`/`xerr=` support (`bar`/`barh`) with matplotlib's expected
lower/upper row shape for the asymmetric case. Without a single shared
normalization step, each of the four chart kinds (and the hue-grouped
variant of `bar`/`barh`) would need to re-implement column-name validation
and symmetric-vs-asymmetric shape handling independently, risking
inconsistent error messages and inconsistent asymmetric-order handling.

## Decision / 決定
Add one module-private helper, `_resolve_error_values(df, spec)`, that
accepts `None` (returns `None`, unchanged rendering path), a single column
name (`str`, returns that column's values as a flat list for symmetric
error), or a 2-element `tuple`/`list` of column names (returns a
`[lower_values, upper_values]` two-row list, preserving the caller's given
`(lower, upper)` order rather than sorting or taking absolute values).
Every referenced column is validated via `_require_columns` before any
plotting occurs, so an invalid column name fails fast with `ValueError`
rather than failing deep inside matplotlib or silently dropping the error
bars. For grouped `bar`/`barh` charts, `_pivot_error_values` calls this same
helper per hue group and reuses `DES-AIDS-074`'s sentinel/duplicate-pivot
logic so the pivoted error table's columns and duplicate-row rejection stay
aligned with the pivoted value table.

## Rejected alternatives / 却下した代替案
- Accepting only symmetric error (a single column name) and leaving
  asymmetric lower/upper errors as a documented non-goal: rejected because
  REQ-AIDS-087's acceptance criteria explicitly require asymmetric
  error-range support, not just symmetric error bars.
- Letting each of `scatter`/`line`/`bar`/`barh` parse its own `xerr`/`yerr`
  argument inline instead of sharing `_resolve_error_values`: rejected
  because it would duplicate the same column-validation and
  symmetric/asymmetric-shape logic four times (plus the hue-grouped
  variant), with no benefit since all four kinds need identical semantics
  for this argument.

## Consequences / 結果
Every chart kind that accepts `xerr`/`yerr` shares identical validation and
shape-normalization behavior, so a caller's `xerr`/`yerr` argument means the
same thing regardless of `kind`. Any future chart kind or grouped-reshape
path that needs error-range support should call
`_resolve_error_values`/`_pivot_error_values` rather than re-implementing
column parsing, to keep error-range semantics (especially asymmetric
lower/upper ordering) consistent across the module.
