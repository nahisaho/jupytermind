# ADR-0076: Treat out-of-order work as a one-shot override recorded beside phase state

## Context / 背景
`DES-AISCI-004` (`REQ-AISCI-006`, `REQ-AISCI-007`, `CHANGE-001`) must block
requests that skip incomplete predecessor phases, while still supporting an
explicit override for one exceptional dispatch. The design trade-off is how
to permit that override without corrupting the canonical active-phase state
or losing the audit trail explaining why out-of-order work happened.

## Decision / 決定
`check_gate(handle, requested_phase, override=None) -> GateDecision` is the
sole phase-order policy surface. It compares the requested phase with the
persisted state, computes the list of incomplete predecessors from
`PHASE_ORDER`, and blocks on the first incomplete predecessor when no
override is supplied. If the requested phase is earlier than the current
active phase but all of its own predecessors are already complete, it is
allowed without an override, preserving safe re-runs of already-completed
earlier phases.

When an override is provided, `check_gate(...)` calls
`record_override(...)` before dispatching the request. The persisted
`OverrideRecord` stores a generated `request_id`, timestamp, requested
phase, human reason, and the full incomplete predecessor list, but leaves
`active_phase`, `completed_phases`, and `incomplete_phases` untouched. That
makes the override explicitly single-use and auditable instead of becoming a
hidden state transition.

## Rejected alternatives / 却下した代替案
- **Temporarily switching `active_phase` to the override target and switching it back later**: rejected — that would make one exceptional request look like a real lifecycle transition and would risk leaving persisted state in the wrong phase if the process crashed or the follow-up mutation were skipped.
- **Requiring an override for any request that does not equal the current active phase, including re-running completed earlier phases**: rejected — the code and tests intentionally permit safe re-execution of an earlier phase when its own predecessors are complete, and forcing overrides there would add noise without protecting any real invariant.
- **Recording override reasons only in the immediate response message or transient logs**: rejected — `DES-AISCI-004` requires the reason and predecessor list to remain queryable afterward, which transient responses and process-local logs do not guarantee.

## Consequences / 結果
Future gate changes must preserve the invariant that overrides are durable
audit records, not lifecycle mutations, and that blocked requests name the
first incomplete predecessor. Covered by the acceptance tests in
`tests/test_ai_scientist_phase_state.py`.
