# ADR-0004: Single-writer async queue for per-notebook write concurrency

## Context / 背景
REQ-AIDS-029 requires that two concurrent analysis sessions targeting the
same project notebook never lose or corrupt cells. nbformat JSON files have
no native multi-writer merge semantics, so concurrent writers must be
coordinated by the skill itself, not by the file format.

## Decision / 決定
Route every notebook mutation (cell append, execution, insight write) for a
given `projects/<project_name>/notebooks/<project_name>.ipynb` path through a
single in-process async write queue keyed by that path, backed by an
OS-level advisory lock file so a second process cannot bypass the queue.
Writers append-serialize; readers read the last fully-flushed JSON.

## Rejected alternatives / 却下した代替案
- Optimistic multi-writer with JSON merge/CRDT reconciliation: rejected as
  disproportionate engineering effort for MVP scope and because notebook
  cell order/evidence links (REQ-AIDS-009/027) are order-sensitive, making
  automatic merge unsafe.
- Per-session notebook forks merged later: rejected because it would break
  REQ-AIDS-011's requirement that reopening the notebook shows the full,
  single, reconstructable analysis history.

## Consequences / 結果
All notebook-writing components (DES-AIDS-003, DES-AIDS-010, and anything
calling through DES-AIDS-004) must go through the Project & Notebook
Manager's write queue rather than writing the ipynb file directly. A second
process holding the lock file is the mechanism a test uses to simulate
concurrent access for REQ-AIDS-029.
