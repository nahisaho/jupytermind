# CHANGE-044: 復旧検証を正規の証拠スキーマに合わせる

## 目的と範囲

全体ゲート復旧の本番コピー作成時に、検証関数が正規の changes.json を拒否した。
musubix3 0.1.22 は order / tdd に schemaVersion 1、
changes に schemaVersion 2 を用いる。実装と fixture は全て 1 と仮定していた。
同じ復旧依頼に含まれる不具合修正として、既存契約への適合を回復する。

Requirements: REQ-GATE-RECOVERY-001

既存要求の Statement / Acceptance と承認済み設計は変更しない。
Python 検証と Node 移送を、artifact ごとの正規バージョンに合わせる。
未知のバージョンを許容せず、changes の旧バージョンも明示的に拒否する。
fixture を実際の正規スキーマに合わせ、両境界の受理・拒否を検証する。

## 実行契約

失敗したコピーは監査用に保持し、本番には移送しない。
実際の fixture による Red は観測済みだが、
CHANGE-042 の同じ要求バッチへの Red 再記録は CLI が拒否した。
その試行を残し、本修正は CHANGE-044 の新しい段階記録で区別する。

以前に承認された要求・設計の保存版と、失敗したコピーにある修正前テストを
段階の入力として配置する。現在の承認済み要求、設計、修正済み fixture を順に戻す。
新しい design 段階より後に、正規 CLI で再度 Red を記録する。
同じテストのまま両実装を修正し、implementation / Green / quality を記録する。
この配置操作を新しい機能仕様の変更や当時の実行とは主張しない。
