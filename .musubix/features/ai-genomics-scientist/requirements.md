# Requirements / 要求

Feature: A new Copilot Agent Skill, `ai-genomics-scientist`, that hosts
domain-specific computational-genomics modules behind a single skill
boundary, analogous to how `ai-data-scientist` hosts generic data-analysis
modules, `ai-scientist` hosts generic research-process phases, and
`ai-chemistry-scientist` / `ai-materials-scientist` host domain-specific
scientific methods. This first increment adds five offline genomics modules
selected by MECE survey of the external ToolUniverse project's genomics
tool taxonomy (used only to identify candidate domains such as
sequence-analysis, variant annotation, splice heuristics, enrichment
analysis, and alignment, not to reuse any of its code, data, or external
API calls). / 新しい Copilot Agent Skill である
`ai-genomics-scientist` は、`ai-data-scientist` が汎用的な
データ解析モジュールを、`ai-scientist` が汎用的な研究プロセス
フェーズを、`ai-chemistry-scientist` と
`ai-materials-scientist` が各専門科学モジュールを保持するのと
同様に、計算ゲノミクス固有のモジュール群を単一スキル境界の
背後に集約する。本初期増分では、外部 ToolUniverse
プロジェクトのゲノミクス系ツール分類を MECE に調査して候補
領域を特定した結果として、配列解析、バリアント注釈、
スプライス部位ヒューリスティック、エンリッチメント解析、
アラインメントの 5 モジュールを追加するが、そのコード、
データ、外部 API 呼び出しは一切再利用しない。

All modules are implemented purely offline in Python with numpy/scipy only;
no network calls and no external bioinformatics libraries such as
Biopython are permitted. Each module validates its own input parameters per
its own stated biological-definedness or numerical-definedness domain and
rejects a request that would be biologically undefined, algorithmically
unsupported, or numerically degenerate before performing any computation,
at the validation granularity (whole-run vs. per-batch-item) that
REQ-AGENOM-003 defines for that module. /
すべてのモジュールは numpy/scipy のみを用いる純粋な
オフライン Python 実装とし、ネットワーク呼び出しや
Biopython などの外部バイオインフォマティクスライブラリは
許可しない。各モジュールは、自身の要求で定義した
生物学的妥当性または数値的妥当性の領域に従って入力
パラメータを検証し、生物学的に未定義、アルゴリズム的に
未対応、または数値的に退化した要求を、当該モジュールに対して
REQ-AGENOM-003 が定義する検証粒度（実行全体かバッチ項目単位か）
で、計算開始前に拒否する。

## REQ-AGENOM-001: Bilingual instruction support / 日英両対応の指示理解
Priority: must
Type: functional
Pattern: ubiquitous
Statement: The system shall preserve the user's request language (Japanese or English) in every user-facing sentence for every module in this genomics skill. / システムは、このゲノミクス技能の全モジュールにおいて、すべてのユーザー向け文でユーザー要求の言語（日本語または英語）を保持しなければならない。
Acceptance: For each of the 5 modules, a fixed Japanese-language fixture request and an English-equivalent fixture request produce responses whose every sentence is in the request language: sequence-features (`"配列特徴量を解析したい"` / `"I want to analyze sequence features"`), variant-effect-annotation (`"コドン変異の効果を注釈したい"` / `"I want to annotate a codon variant effect"`), splice-site-strength (`"スプライス部位強度を評価したい"` / `"I want to score splice-site strength"`), gene-set-enrichment (`"遺伝子セットのエンリッチメントを調べたい"` / `"I want to test gene-set enrichment"`), and pairwise-sequence-alignment (`"2本のDNA配列をアラインメントしたい"` / `"I want to align two DNA sequences"`). In Japanese responses, every non-Japanese token must appear only inside a backtick-delimited code span or an exact double-quoted named-constraint literal; in English responses, no Japanese script character may appear outside a backtick-delimited code span or an exact double-quoted named-constraint literal. / 5 つの各モジュールについて、固定日本語フィクスチャ要求とその英語対応要求は、全文の各文が要求言語で記述された応答を生成する。対象は sequence-features（`"配列特徴量を解析したい"` / `"I want to analyze sequence features"`）、variant-effect-annotation（`"コドン変異の効果を注釈したい"` / `"I want to annotate a codon variant effect"`）、splice-site-strength（`"スプライス部位強度を評価したい"` / `"I want to score splice-site strength"`）、gene-set-enrichment（`"遺伝子セットのエンリッチメントを調べたい"` / `"I want to test gene-set enrichment"`）、pairwise-sequence-alignment（`"2本のDNA配列をアラインメントしたい"` / `"I want to align two DNA sequences"`）である。日本語応答では、すべての非日本語トークンはバッククォート囲みコードスパンまたは完全一致する二重引用符囲み named-constraint リテラルの内部にのみ現れ、英語応答では、日本語スクリプト文字はバッククォート囲みコードスパンまたは完全一致する二重引用符囲み named-constraint リテラルの外側に現れてはならない。
Constraints: A response counts as Japanese if every token outside backtick-delimited code spans and exact double-quoted named-constraint literals contains no ASCII alphabetic character; a response counts as English if every token outside backtick-delimited code spans and exact double-quoted named-constraint literals contains no Hiragana, Katakana, or CJK ideograph character. Code-formatted result objects, parameter names, method identifiers, JSON keys, JSON literals, numbers, and formulas are therefore permitted in either language only when they appear inside backtick-delimited code spans; named-constraint literals are permitted in either language only when they appear exactly inside double quotes. / 応答は、バッククォート囲みコードスパンおよび完全一致する二重引用符囲み named-constraint リテラルの外側にあるすべてのトークンが ASCII 英字を含まない場合に日本語とみなし、同外側にあるすべてのトークンがひらがな、カタカナ、または CJK 統合漢字を含まない場合に英語とみなす。したがって、コード書式の結果オブジェクト、パラメータ名、メソッド識別子、JSON キー、JSON リテラル、数値、式は、バッククォート囲みコードスパン内に現れる場合に限り、いずれの言語でも許可される。named-constraint リテラルは、二重引用符の内部に完全一致で現れる場合に限り、いずれの言語でも許可される。

## REQ-AGENOM-002: Module routing by request content / 要求内容によるモジュール振り分け
Priority: must
Type: functional
Pattern: event-driven
Statement: When a user's request text matches registered name/synonym strings for exactly one distinct supported method after synonym normalization, the system shall dispatch the request to exactly that method's module handler and execute no other module, where the supported methods are sequence-features, variant-effect-annotation, splice-site-strength, gene-set-enrichment, and pairwise-sequence-alignment, each with both an English and a Japanese registered name/synonym list in the manifest. / ユーザー要求テキストが、同義語正規化後に正確に 1 つの distinct な対応メソッドにだけ一致するとき、システムは sequence-features、variant-effect-annotation、splice-site-strength、gene-set-enrichment、pairwise-sequence-alignment のうち該当するただ 1 つのモジュールハンドラにのみ要求を振り分け、英語名と日本語名の登録同義語リストに基づいて他のいかなるモジュールも実行してはならない。
Acceptance: For each of the 5 methods, a fixture request using its registered English name and a separate fixture request using its registered Japanese name each dispatch to exactly that method's handler and no other; a fixture request containing two synonyms that both normalize to the same method still dispatches to that single method and no other; a fixture request containing two different methods' registered names yields a clarification question listing both candidates with no module invoked; a fixture request containing none of the registered names yields a rejection message with no module invoked. / 5 つの各メソッドについて、登録済み英語名を用いたフィクスチャ要求と登録済み日本語名を用いた別個のフィクスチャ要求は、それぞれ対応するただ 1 つのハンドラにのみ振り分けられ、他のハンドラは呼び出されない。同一メソッドに正規化される 2 つの同義語を同時に含むフィクスチャ要求は、その単一メソッドにのみ振り分けられる。2 つの異なるメソッド登録名を同時に含むフィクスチャ要求は、両候補を列挙する確認質問を返し、モジュールは何も起動しない。登録名を 1 つも含まないフィクスチャ要求は、モジュール未起動のまま拒否メッセージを返す。
Constraints: Matching uses Unicode NFKC normalization on both the request text and every registered name/synonym string, then a case-insensitive substring test on the normalized forms. All matched strings are mapped to their owning method, and duplicate hits that map to the same owning method are collapsed before counting the number of distinct matched methods. / マッチングは、要求テキストと各登録名・同義語文字列の双方に Unicode NFKC 正規化を適用し、その正規化後文字列に対して大文字小文字を区別しない部分文字列判定を行う。すべての一致文字列は所有メソッドへ写像され、同一所有メソッドに写像される重複ヒットは distinct な一致メソッド数を数える前に畳み込まれる。

## REQ-AGENOM-003: Input and parameter validation / 入力・パラメータ検証
Priority: must
Type: functional
Pattern: unwanted-behavior
Statement: If a requested module's input parameters fail that module's own documented biological-validity, alphabet-validity, or numerical-adequacy domain, then the system shall reject the invalid scope defined for that module (the whole run or the individual batch item) and report which parameter violated which named constraint before producing any result for that invalid scope. / 要求されたモジュールの入力パラメータが、そのモジュール自身の要求で文書化された生物学的妥当性、アルファベット妥当性、または数値的十分性の領域を満たさない場合、システムはそのモジュールに対して定義された無効スコープ（実行全体または個別バッチ項目）を拒否し、その無効スコープに対する結果を一切生成する前に、どのパラメータがどの名前付き制約に違反したかを報告しなければならない。
Acceptance: A sequence-feature batch request validates each sequence independently: in the fixture batch `["ATGGCCATTGTAATGGGCCGCTGAAAGGGTGCCCGATAG", "ATBX"]`, index 0 is computed normally while index 1 is rejected naming the `sequence` parameter and the constraint "must be a non-empty uppercase DNA string over {A,C,G,T} with length >= 3". A variant-effect request with `ref_codon="TGG"`, `position=2`, and `alt_base="G"` is rejected naming `alt_base` and the constraint "alt_base must differ from the reference base at position". A splice-site request with `window="CAGGCAAGT"` is rejected naming `window` and the constraint "position 0,+1 must be the canonical GT dinucleotide". A gene-set-enrichment request containing `query_genes=["GENE01","BADGENE"]` is rejected naming `query_genes` and listing the invalid gene `"BADGENE"`. An alignment request with `seq1="GATTACA"` and `seq2="GCXTGCA"` is rejected naming `seq2` and the constraint "must be a non-empty uppercase DNA string over {A,C,G,T}". / 配列特徴量バッチ要求は各配列を独立に検証する。フィクスチャバッチ `["ATGGCCATTGTAATGGGCCGCTGAAAGGGTGCCCGATAG", "ATBX"]` では index 0 は通常計算される一方、index 1 は `sequence` パラメータと制約 "must be a non-empty uppercase DNA string over {A,C,G,T} with length >= 3" を明示して拒否される。`ref_codon="TGG"`、`position=2`、`alt_base="G"` のバリアント効果要求は `alt_base` と制約 "alt_base must differ from the reference base at position" を明示して拒否される。`window="CAGGCAAGT"` のスプライス部位要求は `window` と制約 "position 0,+1 must be the canonical GT dinucleotide" を明示して拒否される。`query_genes=["GENE01","BADGENE"]` を含む遺伝子セット要求は `query_genes` を明示し、無効遺伝子 `"BADGENE"` を列挙して拒否される。`seq1="GATTACA"` と `seq2="GCXTGCA"` のアラインメント要求は `seq2` と制約 "must be a non-empty uppercase DNA string over {A,C,G,T}" を明示して拒否される。
Constraints: This requirement's "biological-validity, alphabet-validity, or numerical-adequacy domain" is defined per module by REQ-AGENOM-010/020/030/040/050; it does not itself define a single universal validity test applicable across all five modules. Validation granularity is per module: REQ-AGENOM-010 validates and rejects each batch item independently without aborting the rest of the batch; REQ-AGENOM-020/030/040/050 validate the whole run atomically and reject the entire run with no partial computation when any parameter is invalid. / 本要求の「生物学的妥当性、アルファベット妥当性、または数値的十分性の領域」は REQ-AGENOM-010/020/030/040/050 がモジュールごとに定義するものであり、5 モジュールすべてに適用される単一の普遍的妥当性判定を本要求自体が定義するものではない。検証粒度はモジュールごとに異なり、REQ-AGENOM-010 はバッチ項目ごとに独立検証して他項目を中断せず、REQ-AGENOM-020/030/040/050 はいずれかのパラメータが無効なら部分計算を行わず実行全体を原子的に拒否する。

## REQ-AGENOM-004: Reproducible run evidence / 再現可能な実行根拠
Priority: must
Type: functional
Pattern: event-driven
Statement: When a module run completes, the system shall record a deterministic result (produced without any random seed) with exactly three top-level keys: `metadata` (a JSON-safe dict containing at least `module`, `schema_version`, `numpy_version`, and `scipy_version`), `parameters` (a JSON-safe dict of the resolved input parameters), and `result` (a JSON-safe dict or list of the module's output values). / モジュール実行が完了したとき、システムは乱数シードを用いずに生成された決定論的結果を、最上位キーをちょうど 3 つ、すなわち `metadata`（少なくとも `module`、`schema_version`、`numpy_version`、`scipy_version` を含む JSON 安全な辞書）、`parameters`（解決済み入力パラメータの JSON 安全な辞書）、`result`（モジュール出力値の JSON 安全な辞書またはリスト）として記録しなければならない。
Acceptance: For each of the 5 modules, two runs with identical `parameters` against the same installed numpy/scipy versions produce a run record whose exact top-level key set is `{"metadata","parameters","result"}` and whose `metadata` contains at least `module`, `schema_version`, `numpy_version`, and `scipy_version`; the two runs' `result` values compare exactly equal for strings, booleans, integers, nulls, lists, and dictionaries whose recursively corresponding non-float leaves are equal, and compare within `1e-9` absolute tolerance for float leaves; `metadata.numpy_version` matches the installed `numpy.__version__` string and `metadata.scipy_version` matches the installed `scipy.__version__` string. / 5 つの各モジュールについて、同一の `parameters` を同一の numpy/scipy インストール版で 2 回実行すると、得られる RunRecord の最上位キー集合は厳密に `{"metadata","parameters","result"}` であり、`metadata` は少なくとも `module`、`schema_version`、`numpy_version`、`scipy_version` を含む。また、2 回の実行の `result` は文字列、真偽値、整数、null、リスト、および再帰的に対応する非浮動小数葉が等しい辞書について完全一致し、浮動小数葉については絶対誤差 `1e-9` 以内で一致する。さらに、`metadata.numpy_version` はインストール済み `numpy.__version__` 文字列と一致し、`metadata.scipy_version` はインストール済み `scipy.__version__` 文字列と一致する。
Constraints: "Deterministic" means every module's governing computation (ORF scanning, standard-genetic-code translation, fixed splice-site log-odds scoring, `scipy.stats.hypergeom.sf`, or Needleman-Wunsch dynamic programming with fixed tie-break order) is a pure function of `parameters` and the installed numpy/scipy versions, with no stochastic step and therefore no seed to record. / 「決定論的」とは、各モジュールの支配計算（ORF 走査、標準遺伝暗号翻訳、固定スプライス部位対数オッズスコア、`scipy.stats.hypergeom.sf`、または固定タイブレーク順序付き Needleman-Wunsch 動的計画法）が `parameters` とインストール済み numpy/scipy 版の純関数であり、確率的ステップを含まず、そのため記録すべきシードも存在しないことを意味する。

## REQ-AGENOM-010: Sequence feature analysis / 配列特徴量解析
Priority: must
Type: functional
Pattern: event-driven
Statement: When a user requests sequence feature analysis for one or more DNA sequences, the system shall return, for each valid sequence, a result object with exactly the keys `length`, `gc_content`, `longest_orf`, and `codon_usage`, computed by the fixed forward-frame algorithm documented in this requirement's constraints. / ユーザーが 1 個以上の DNA 配列に対する配列特徴量解析を要求したとき、システムは各有効配列について、`length`、`gc_content`、`longest_orf`、`codon_usage` のちょうど 4 キーを持つ結果オブジェクトを、本要求の制約で文書化した固定の順方向読み枠アルゴリズムに従って返さなければならない。
Acceptance: For the reference sequence `"ATGGCCATTGTAATGGGCCGCTGAAAGGGTGCCCGATAG"` (verified by executable Python fixture code), the computed output is exactly `length = 39`, `gc_content = 0.5641025641025641`, `longest_orf = {"frame": 0, "start_index": 0, "length": 24}`, and `codon_usage = {"ATG": 2, "ATT": 1, "CGC": 1, "GCC": 1, "GGC": 1, "GTA": 1, "TGA": 1}`. A batch request of `["ATGGCCATTGTAATGGGCCGCTGAAAGGGTGCCCGATAG", "ATBX"]` returns the computed result above at index 0 and a per-item rejection at index 1, without aborting the whole batch. / 参照配列 `"ATGGCCATTGTAATGGGCCGCTGAAAGGGTGCCCGATAG"` に対して（実行可能 Python フィクスチャコードで検証済み）、計算出力は厳密に `length = 39`、`gc_content = 0.5641025641025641`、`longest_orf = {"frame": 0, "start_index": 0, "length": 24}`、`codon_usage = {"ATG": 2, "ATT": 1, "CGC": 1, "GCC": 1, "GGC": 1, "GTA": 1, "TGA": 1}` となる。`["ATGGCCATTGTAATGGGCCGCTGAAAGGGTGCCCGATAG", "ATBX"]` のバッチ要求は、index 0 に上記計算結果を返し、index 1 にはバッチ全体を中断せずに項目単位の拒否を返す。
Constraints: A valid `sequence` is a non-empty uppercase string over the exact alphabet `{A,C,G,T}` with length `>= 3`; invalid sequences are rejected per item under REQ-AGENOM-003. `length = len(sequence)` and `gc_content = (count('G') + count('C')) / length`. `longest_orf` is the single longest ORF found by scanning frames 0, 1, and 2 only (no reverse complement) for a subsequence that starts at `ATG` and ends at the first following in-frame stop codon in `{TAA, TAG, TGA}`, reported as `{frame, start_index, length}` with 0-based `start_index` into the original sequence. ORF tie-break order is fixed: when multiple ORFs share the maximum length, choose the one with the lowest `frame`, and if frames are equal choose the one with the lowest `start_index`. The ORF includes both the start codon and the terminating stop codon. `codon_usage` is the integer-count dictionary of non-overlapping codons inside that longest ORF, including the stop codon; if no ORF exists, `longest_orf` is `null` and `codon_usage` is `{}`. / 有効な `sequence` は、正確に `{A,C,G,T}` のアルファベットのみからなる空でない大文字列であり、長さは `>= 3` でなければならず、無効な配列は REQ-AGENOM-003 に従って項目単位で拒否される。`length = len(sequence)`、`gc_content = (count('G') + count('C')) / length` である。`longest_orf` は、3 つの順方向読み枠 0・1・2 のみ（逆相補鎖なし）を走査し、`ATG` で開始し、その後最初に現れるインフレーム停止コドン `{TAA, TAG, TGA}` で終わる部分配列のうち単一最長の ORF を、元配列に対する 0 始まり `start_index` を含む `{frame, start_index, length}` として表したものである。ORF のタイブレーク順序は固定であり、同じ最大長の ORF が複数ある場合は最小の `frame` を選び、それでも同じなら最小の `start_index` を選ぶ。ORF は開始コドンと停止コドンを両方含む。`codon_usage` はその最長 ORF 内の停止コドンを含む非重複コドン整数頻度辞書であり、ORF が存在しない場合は `longest_orf` は `null`、`codon_usage` は `{}` である。

## REQ-AGENOM-020: Variant effect heuristic annotation / バリアント効果ヒューリスティック注釈
Priority: must
Type: functional
Pattern: event-driven
Statement: When a user requests variant effect heuristic annotation for a single-codon substitution, the system shall validate `ref_codon` as exactly 3 bases from `{A,C,G,T}`, validate `position` as an integer in `{0,1,2}`, validate `alt_base` as exactly 1 base from `{A,C,G,T}` distinct from `ref_codon[position]`, compute `alt_codon` by substituting `alt_base` at `position`, translate both codons with the standard genetic code (NCBI translation table 1), and report `{ref_codon, alt_codon, ref_amino_acid, alt_amino_acid, effect}` where `effect` is classified as `"synonymous"` when both translated amino acids are equal and non-stop, `"nonsense"` when the reference amino acid is non-stop and the alternate amino acid is `"*"`, `"missense"` when both amino acids are non-stop and different, and `"readthrough"` when the reference amino acid is `"*"` and the alternate amino acid is non-stop. / ユーザーが単一コドン置換のバリアント効果ヒューリスティック注釈を要求したとき、システムは `ref_codon` が `{A,C,G,T}` からなるちょうど 3 塩基であること、`position` が `{0,1,2}` の整数であること、`alt_base` が `{A,C,G,T}` からなるちょうど 1 塩基であり `ref_codon[position]` と異なることを検証し、`position` に `alt_base` を代入して `alt_codon` を構成し、両コドンを標準遺伝暗号（NCBI translation table 1）で翻訳し、`effect` を、両翻訳アミノ酸が等しくかつ非停止なら `"synonymous"`、参照アミノ酸が非停止かつ代替アミノ酸が `"*"` なら `"nonsense"`、両者が非停止かつ異なるなら `"missense"`、参照アミノ酸が `"*"` かつ代替アミノ酸が非停止なら `"readthrough"` と分類して、`{ref_codon, alt_codon, ref_amino_acid, alt_amino_acid, effect}` を報告しなければならない。
