# Requirements / 要求

Feature: A new Copilot Agent Skill, `ai-structural-biology-scientist`, that
hosts domain-specific structural-biology modules behind a single skill
boundary, analogous to how `ai-chemistry-scientist` hosts cheminformatics
modules and `ai-materials-scientist` hosts computational-materials-science
modules. 新しい Copilot Agent Skill `ai-structural-biology-scientist` は、
`ai-chemistry-scientist` の化学情報学モジュール群や
`ai-materials-scientist` の計算材料科学モジュール群と同様に、構造生物学
固有のモジュールを単一の skill 境界の内側に集約して提供する。

This first increment adds five modules selected by survey of the external
ToolUniverse project's structural-biology taxonomy only as domain-
identification inspiration (never reusing its code, data, or API calls): a
secondary-structure heuristic, a per-residue hydrophobicity/burial
heuristic, a protein-protein docking-score heuristic, structural similarity
by RMSD after optimal superposition, and a residue contact-map heuristic.
この初期版では、外部 ToolUniverse プロジェクトの構造生物学ツール分類を、
あくまで候補領域の同定の参考としてのみ用い（コード・データ・API 呼び出しは
一切再利用しない）、二次構造ヒューリスティック、残基ごとの疎水性・埋没度
ヒューリスティック、タンパク質間ドッキングスコア・ヒューリスティック、
最適重ね合わせ後 RMSD による構造類似性、残基コンタクトマップ・
ヒューリスティックの 5 モジュールを追加する。

All modules are implemented purely offline in Python/numpy, with no network
calls, no external structural-biology libraries such as Biopython or PyMOL,
and no real PDB/mmCIF parsing beyond simple inline coordinate lists supplied
by the caller. Every module validates its own input parameters for
biochemical or numerical definedness and rejects invalid input before
performing any computation. すべてのモジュールは Python/numpy のみで
完全オフライン実装され、ネットワーク呼び出し、Biopython や PyMOL の
ような外部構造生物学ライブラリ、ならびに呼び出し側が渡す単純なインライン
座標列を超える実 PDB/mmCIF 解析を用いない。各モジュールは自身の生化学的・
数値的な定義域に対して入力検証を行い、無効な入力を計算開始前に拒否する。

## REQ-ASTRUCT-001: Bilingual instruction support / 日英両対応の指示理解
Priority: must
Type: functional
Pattern: ubiquitous
Statement: The system shall accept user requests and produce user-facing messages in whichever of Japanese or English the user's request used, for every module in this structural-biology skill. システムは、この構造生物学 skill の全モジュールについて、ユーザー要求が日本語であれば日本語で、英語であれば英語で、ユーザー向けメッセージを生成しなければならない。
Acceptance: A fixed Japanese-language fixture request ("二次構造をヒューリスティックに評価したい") produces a response whose every sentence is Japanese prose (English technical tokens limited to method names, unit symbols, and numeric values are permitted); the English-equivalent fixture request ("I want to evaluate secondary structure heuristically") produces an all-English response; neither response contains a sentence mixing Japanese and English prose. 固定日本語フィクスチャ要求「二次構造をヒューリスティックに評価したい」では全文が日本語の応答となり、対応する英語フィクスチャ要求 "I want to evaluate secondary structure heuristically" では全文が英語の応答となり、いずれの応答にも日本語と英語の散文が同一文内で混在する文は存在しない。

Priority: must
Type: functional
Pattern: unwanted-behavior
Statement: If a requested module's input parameters fail that module's own documented biochemical-validity, geometric-definedness, or numerical-adequacy domain, then the system shall reject the run and report which parameter violated which named constraint before performing any lookup, averaging, scoring, superposition, or contact calculation. 要求されたモジュールの入力パラメータが、そのモジュール自身の文書化された生化学的妥当性・幾何学的定義可能性・数値的十分性の定義域を満たさない場合、システムは、どのパラメータがどの名前付き制約に違反したかを報告してその実行を拒否し、いかなる lookup、平均化、スコア計算、重ね合わせ、コンタクト計算も行ってはならない。
Acceptance: A sequence-based request containing a non-standard residue code — for example `"MKXB"` — is rejected before computation with a message naming the `sequence` parameter and the first invalid character and index (`'X'` at index 2 for this fixture); a hydrophobicity request with `window_size = 4` is rejected naming `window_size` and the constraint "must be a positive odd integer"; a docking request with `interface_area_A2 = -10.0` is rejected naming `interface_area_A2` and the constraint "must be > 0"; and the same reject-before-computation pattern applies to every module-specific domain listed in REQ-ASTRUCT-010/020/030/040/050. たとえば `"MKXB"` のように非標準残基コードを含む配列要求は、計算前に `sequence` パラメータと最初の不正文字および位置（このフィクスチャでは index 2 の `'X'`）を明示して拒否される。`window_size = 4` の疎水性要求は `window_size` と制約 "must be a positive odd integer" を明示して拒否される。`interface_area_A2 = -10.0` のドッキング要求は `interface_area_A2` と制約 "must be > 0" を明示して拒否される。REQ-ASTRUCT-010/020/030/040/050 に記載された各モジュール固有の定義域にも、この「計算前に拒否し、パラメータ名と制約名を示す」という同一パターンが適用される。
Constraints: This requirement's "biochemical-validity, geometric-definedness, or numerical-adequacy domain" is defined per module by REQ-ASTRUCT-010/020/030/040/050; it does not itself define a single universal validity test across all five modules. この要求でいう「生化学的妥当性・幾何学的定義可能性・数値的十分性の定義域」は REQ-ASTRUCT-010/020/030/040/050 がモジュールごとに定義するものであり、5 モジュールすべてに一律適用される単一の普遍的妥当性検査をここで定義するものではない。

## REQ-ASTRUCT-004: Reproducible run evidence / 再現可能な実行根拠
Priority: must
Type: functional
Pattern: event-driven
Statement: When a module run completes, the system shall record a deterministic `RunRecord` with exactly three top-level keys: `metadata`, `parameters`, and `result`, where `metadata` contains at least `module`, `schema_version`, and `numpy_version`. モジュール実行が完了したとき、システムは、トップレベルキーを厳密に `metadata`、`parameters`、`result` の 3 つだけ持つ決定論的な `RunRecord` を記録しなければならず、`metadata` は少なくとも `module`、`schema_version`、`numpy_version` を含まなければならない。
Acceptance: For each of the 5 modules, two runs with identical `parameters` against the same installed numpy version in the Python environment running the skill produce `result` values that compare exactly equal for strings, booleans, integers, and list/dict structure, and within `1e-9` absolute tolerance for floating-point fields; `metadata.numpy_version` matches that environment's installed `numpy.__version__` string. 5 モジュールの各々について、同一の `parameters` と、skill を実行する Python 環境にインストールされた同一の numpy バージョンで 2 回実行したとき、`result` は文字列・真偽値・整数・list/dict 構造については完全一致し、浮動小数点フィールドについては絶対誤差 `1e-9` 以内で一致する。また `metadata.numpy_version` は、その環境が報告する `numpy.__version__` と一致する。
Constraints: "Deterministic" means every module's governing computation is a pure function of `parameters` and the installed numpy version, with no stochastic step and therefore no random seed to record. 「決定論的」とは、各モジュールの支配的計算が `parameters` とインストール済み numpy バージョンの純関数であり、確率的ステップを持たず、したがって記録すべき乱数 seed も存在しないことを意味する。

## REQ-ASTRUCT-030: Protein-protein docking-score heuristic / タンパク質間ドッキングスコア・ヒューリスティック
Priority: must
Type: functional
Pattern: event-driven
Statement: When a user requests a protein-protein docking score for two interface residue-composition specifications and an interface area, the system shall return `{size_term, hydrophobic_complementarity, charge_complementarity, score}` computed from partner A and partner B records of the form `{hydrophobic_count, charged_count}` with each count a finite non-negative integer and from a finite `interface_area_A2 > 0`, using the fixed formulas `size_term = clip(1 - abs(interface_area_A2 - 800.0) / 800.0, 0, 1)`, `hydrophobic_complementarity = min(A.hydrophobic_count, B.hydrophobic_count) / max(1, A.hydrophobic_count + B.hydrophobic_count)`, `charge_complementarity = min(A.charged_count, B.charged_count) / max(1, A.charged_count + B.charged_count)`, and `score = 0.5*size_term + 0.25*hydrophobic_complementarity + 0.25*charge_complementarity`. ユーザーが 2 つの界面残基組成仕様と界面面積に対するタンパク質間ドッキングスコアを要求した場合、システムは partner A と partner B を `{hydrophobic_count, charged_count}` 形式の record として受け付け、各 count を有限な非負整数、`interface_area_A2` を有限かつ `> 0` の値として検証したうえで、固定式 `size_term = clip(1 - abs(interface_area_A2 - 800.0) / 800.0, 0, 1)`、`hydrophobic_complementarity = min(A.hydrophobic_count, B.hydrophobic_count) / max(1, A.hydrophobic_count + B.hydrophobic_count)`、`charge_complementarity = min(A.charged_count, B.charged_count) / max(1, A.charged_count + B.charged_count)`、`score = 0.5*size_term + 0.25*hydrophobic_complementarity + 0.25*charge_complementarity` から `{size_term, hydrophobic_complementarity, charge_complementarity, score}` を返さなければならない。
